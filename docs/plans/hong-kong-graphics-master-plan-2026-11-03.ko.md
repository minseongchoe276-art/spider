# 홍콩 맵 그래픽·렌더링·품질 종합 기획서

기준일: 2026-11-03. 대상은 홍콩 3D Tiles를 사용하는 약 4.8km × 4.8km 플레이 범위다. 목표는 주요 플레이 경로에서 찢어진 외형, 갑작스러운 타일 전환, 불안정한 지면과 심한 프레임 끊김을 줄이고, 도심·산지·해안을 일관된 품질로 보여주는 것이다. 실제 홍콩의 지리와 건물 위치를 유지한다.

## 1. 현재 상태와 판단 근거

- 현재 지형은 `src/UrbanGroundCity.js`에서 외부 F2 사진 측량 3D Tiles 한 계층을 스트리밍한다. 해당 사진 메시에는 지면·건물·교량이 함께 들어 있으므로 건물만 일괄 삭제하거나 평평한 바닥을 깔면 시각과 충돌이 어긋날 수 있다.
- 11월 1일 격자 조사에서 49개 지점 모두 지형 표면과 메시가 감지됐고 당시 수집된 실패 타일과 셰이더 오류는 없었다. 이는 셀당 한 시점의 표본이며 모든 건물, 각도, LOD 또는 실제 이동 경로가 정상이라는 뜻은 아니다. 원본 화면과 기록은 `docs/qa/hong-kong-repair-2026-10-29/current/`에 있다.
- 11월 3일 재점검은 5개 셀 이후 실행 문맥이 사라져 중단됐으며 전체 재검증으로 취급하지 않는다. `docs/qa/hong-kong-repair-2026-10-29/audit-2026-11-03/regions.json` 참조.
- 화면에서 산지와 수목의 삼각형 덩어리, 건물과 도로의 늘어진 사진, 해상 격자 및 해안 경계가 확인됐다. 개별 위치는 아래 격자 목록과 원본 이미지를 출발점으로 사용하고 가까운 실제 플레이 시점에서 원인을 재확인한다.
- 11월 3일 Chrome headless 단일 전후 측정은 평균 46.95→48.05 FPS, 프레임 간격 p99 66.7→83.3ms였다. 프레임 측정 조건과 로딩 상태가 완전히 같지 않아 개선율로 확정하지 않는다. 발 접촉 관련 기존 실패와 남은 사례는 `docs/qa/hong-kong-improvement-2026-11-03/RESULT.ko.md`에 있다.
- 현재 low/balanced/high의 지형 오류 목표는 8/8/4px, 요청 거리는 450/650/1000m다. 장치 조건에 따라 캐시 한도는 96~640MiB이며 이는 총 GPU 메모리가 아니다. 수면은 현재 높이와 표면 기울기를 이용한 재질 처리로, 해안선·육지 오분류와 실제 화면은 추가 확인이 필요하다.

## 2. 품질 목표와 완료 판정

다음 수치는 **제안 목표**이며 현재 달성치가 아니다. 기준 기기와 경로를 먼저 확정하고 실제 측정값에 맞게 조정한다.

| 구분 | 목표 | 확인 방법 |
|---|---|---|
| 시작·대표 도심 경로 | 플레이어 0~30m에서 눈에 띄는 찢김, 겹친 벽, 깜박임, 텍스처 누락 0건 | 고정 위치와 실제 걷기·점프·와이어·차량 영상, 전후 캡처 |

### 구역별 작업 우선순위

1. **시작점과 중심 도심 (0,0 및 인접 셀):** 시작 테라스·보행교·6개 검토 외벽과 수목 보강의 경계부터 보행 시점으로 조사한다. 49셀의 중앙 화면은 상공 시점이므로 거리 수준 품질의 근거로 쓰지 않는다. 대표 결함마다 타일 ID, 좌표, 시점, 충돌 표면을 기록하고 지면·벽·난간을 순서대로 보강한다.
2. **도심 밀집과 고층 (예: 700,700 및 -1400,0):** 늘어난 외벽, 옥상, 타워 하단, 교량 접점을 구분한다. 같은 건물의 외곽선과 높이를 확인한 뒤 면별 교체 데이터를 만든다. 전 건물에 같은 창문을 자동 적용하지 않는다.
3. **산지와 수목 (예: -700,-1400, 2100,-2100):** 원본 지형의 큰 삼각형, 나무 덩어리, 경사면 경계를 분리해 본다. 보행 가능 경로와 가까운 능선부터 지형 메시 및 식생을 제작한다. 광역 숲은 원거리 대체 모델과 밀도 예산을 따로 정한다.
4. **해안과 항만 (예: 0,2100, 2100,2100):** 수면 타일의 색·격자 경계와 부두·선박·육지 경계를 재현한다. 현 수면 셰이더의 높이·기울기 조건이 낮은 도로/부두를 물로 오분류하는지 확인하고 지리 기반 수면 경계 데이터를 확보한 뒤 수면 메시를 연결한다. 물리 충돌과 시각 면의 용도는 명시한다.
5. **나머지 모든 셀:** 표 위의 각 이미지를 통해 유형을 확정하고, 카메라 4방향과 실제 지상 접근 가능 여부를 추가 기록한다. 접근이 어려운 셀은 원거리 품질과 경계부터 처리하며 조사 누락으로 남기지 않는다.

## 4. 요소별 구현 기획

### 4.1 지형·도로·보도

근거리 접근 경로의 도로, 보도, 계단, 테라스를 원본 표면과 좌표가 맞는 메시로 교체한다. 표면 종류별 색·거칠기·텍셀 밀도를 정하고 차도, 보도, 턱이 구분되게 한다. 경계는 원본의 실제 삼각형 또는 검토된 폴리곤 단위로 소유권을 부여한다. 교체 메시가 준비되면 렌더와 충돌을 같은 프레임에 전환하고, 실패 시 기존 지지면을 유지한다. 건물 진입구, 차량 바퀴, 카메라와 발 접촉을 함께 확인한다.

### 4.2 건물·옥상·외벽

건물별 외곽과 층수를 확인해 주요 외벽 및 옥상을 교체한다. 입면 유형을 유리·콘크리트·상점·주거로 구분하고 창 크기, 기단, 모서리, 옥상 설비를 건물 유형에 맞춘다. `HongKongDistrict.js`의 검토된 6개 면과 실제 원본의 겹침부터 확인한다. 텍스처와 기하가 늘어난 면은 UV만 다듬어 복구 가능한지 판정하고, 손실된 형상은 새 모델로 제작한다. 벽 타기·와이어 앵커와 충돌을 동일한 표면에 맞춘다.

### 4.3 수목·산지

중앙의 검토된 수목 위치와 자동 후보를 분리 관리하고, 식생 색만으로 건물이나 잔디를 제거하지 않는다. 수목별 중심·지면 높이·수관 경계를 검토한 뒤 원본 교체 범위와 대체 모델을 함께 등록한다. 높이와 수관 모양이 다른 모델을 사용하고 가까운 영역부터 교체한다. 산지는 경사와 실루엣을 보존하며 가시 거리에 따라 메시 밀도를 달리한다. 원본 마스크와 충돌 불일치를 확인해 보이지 않는 장애물과 지면 구멍을 제거한다.

### 4.4 해안·수면

실제 수면 범위를 폴리곤으로 구하고 육지·부두·도로와 경계를 맞춘다. 해수면 높이는 좌표계와 원본을 기준으로 조사하며 현재 0m 가정을 검증한다. 잔물결은 시간과 월드 좌표를 사용해 타일 경계가 보이지 않게 하고, 원거리에는 낮은 비용의 표현을 쓴다. 낮·밤·비에서 해안 색차와 깜박임을 확인한다. 현 높이 기반 셰이더는 새로운 경계 데이터 적용 전후의 오분류 검사 대상이다.

### 4.5 조명·재질·날씨

사진에 이미 들어 있는 그림자와 실시간 조명을 같은 위치에서 비교한다. Basic과 Standard 재질이 낮·밤에 다르게 반응하는 구간을 기록해 보강 자산의 명도와 거칠기를 맞춘다. 태양 그림자는 플레이어 주변에 집중하고 보강 건물의 접촉 그림자를 비교한다. 밤 창문과 가로등은 실제 건물/보도 위치와 일치하도록 배치한다. 흐림, 비, 젖은 도로를 단계적으로 확인하고 노출 조정으로 원본 결함을 가리지 않는다.

### 4.6 스트리밍·로딩·오류 복구

`HongKongRendering.js`, `UrbanGroundCity.js`, `TileRecovery.js`, `TileRenderPreparation.js`, `TileTextures.js`를 한 흐름으로 측정한다. 시야 회전과 고속 이동 시 근거리 상세 타일과 발밑 충돌을 우선하고, 캐시 압력에서는 거리와 요청량을 조절한다. 부모/자식 교체 중 빈 공간, 디코딩 실패와 재시도, 셰이더 준비 지연, GPU 컨텍스트 복구를 관찰한다. 원본 텍스처의 색공간·UV·밉맵을 유지한다. 모바일에서 상세도 증가로 캐시가 계속 거절되는 상황도 별도로 측정한다.

### 4.7 성능·표현 설정

근거리 교체 모델은 인스턴싱과 공유 재질을 사용하고 원거리 LOD를 준비한다. 프레임 시간과 함께 CPU 작업, draw call, 삼각형 수, 타일 캐시, 네트워크, JS heap을 각각 기록한다. GPU 메모리를 타일 캐시 수치로 추정하지 않는다. low는 수목·그림자·거리, balanced는 근거리 품질과 안정성, high는 원거리 디테일을 중심으로 개별 기기에서 조정한다. 동적 해상도는 글자/UI와 지도에 미치는 영향도 확인한다.

### 4.8 미니맵·전체 지도

미니맵은 본 화면과 다른 삼각형 예산을 사용하므로 건물 누락과 방향을 별도로 확인한다. `Minimap.js`의 메시 선택 제한과 신규 보강 메시를 비교하고, 필요하면 단순화된 지도 전용 메시를 만든다. 전체 지도는 OSM 타일 실패·느린 연결 시 위치 표식과 로딩 안내가 유지되는지, 해안선 및 방향이 3D 위치와 맞는지 점검한다.

## 5. 데이터 구조와 전환

구역별 작업 데이터에는 ID, 버전, 경계 폴리곤, 원본 타일 및 좌표계, 모델/재질 경로, 충돌 메시, LOD, 사용 출처와 검수 상태를 기록한다. 상태 흐름은 `원본 활성 → 대체 리소스 로딩 → 렌더·충돌 준비 → 동시 전환 → 원본 해제`로 설계한다. 로딩·컴파일·충돌 생성 실패 또는 타일 축출 시 기존 표면을 유지하고 재시도한다. 재진입과 품질 변경에도 중복 생성·누수가 없도록 한다. 외부 데이터·모델은 이용 조건과 배포 권한을 확인하고 개인 정보나 인증 정보는 기록하지 않는다.

## 6. 단계별 실행과 산출물

| 단계 | 작업·대상 | 산출물 및 완료 조건 |
|---|---|---|
| 0. 기준 확보 | 49셀 재실행, 네 방향, 카메라/LOD/실패 상태 기록 | 결함별 좌표·이미지·원인 가설·우선순위. 중단된 셀을 미완료로 기록 |
| 1. 스트리밍 안정화 | 로딩, 재시도, 타일·충돌 전환, 해안 오분류 | 느린 네트워크·오류 주입 영상, 기존 지지면 유지 및 복구 |
| 2. 시작 구역 | 80~120m 대표 이동 경로의 지면·외벽·수목·난간 | 동일 시점 전후 화면, 걷기·벽 타기·와이어·차량 검사 |
| 3. 도심 확장 | 고층·도로·보행교를 구역 단위 교체 | 구역별 모델/충돌 및 성능 예산, 결함별 닫힘 기록 |
| 4. 산지·수변 | 접근 경로의 지형·수목·해안과 수면 | 경계·실루엣·충돌·수면 검수, 낮/밤 비교 |
| 5. 최적화·출시 검토 | 기기별 프리셋, 장시간 이동, 지도·날씨 | 목표 기기 반복 측정, 실패 목록과 잔여 미검증 범위 |

일정과 인력은 대표 구역 제작량과 실제 기기 측정 후 산정한다. 전체 교체를 수치만으로 약속하지 않고 각 구역의 사용 빈도와 결함 심각도에 따라 우선순위를 갱신한다.

## 7. 검증 절차

- 기준 장면: 시작점, 보도, 교차로, 옥상, 조경, 해안, 산지, 고속 이동의 위치와 카메라를 저장한다. 같은 시각·날씨·품질·해상도에서 로딩 직후와 안정 후를 비교한다.
- 기능: 걷기·점프·벽 타기·와이어·차량 진입/주행·카메라 충돌·미니맵/전체 지도를 실제 입력으로 확인한다. 교체 전후 충돌·지지 높이와 보이지 않는 장애물을 비교한다.
- 실패: 타일 404/일시 중단, 느린 응답, 디코드 오류, 캐시 포화, 컨텍스트 손실과 복구를 재현한다. 셰이더 오류와 요청 취소를 구별한다.
- 관련 기존 명령: `npm run test:hong-kong:rendering`, `node scripts/check-hong-kong-tile-recovery.mjs`, `node scripts/check-hong-kong-start-district.mjs`, `node scripts/check-hong-kong-wall-fall.mjs`, `npm run build`. 변경 범위에 맞게 실제 WebGL 장면과 기기 검사를 추가한다. 이 문서 작성 자체에서 명령을 실행했다는 뜻은 아니다.
- 장시간: 동일 경로를 최소 15분 왕복하고 전후 FPS 분포·메모리·오류를 기록한다. 데스크톱/모바일 기기명과 브라우저, 네트워크를 명시한다. 시각 승인 전 실기기 화면을 비교한다.

## 8. 주요 위험과 의사결정

원본 데이터가 이미 잃은 디테일은 필터로 복원할 수 없고 정확한 교체 모델과 검토 비용이 필요하다. 넓은 마스크·전역 수면 평면은 도로와 시설을 가릴 수 있으며 충돌과 시각이 어긋날 수 있다. 상세도와 캐시 예산을 무조건 올리면 저사양 기기에서 로딩과 메모리가 악화될 수 있다. 지리 기반 수면 자료, 대체 모델 사용 권한, 실기기 확보 여부와 목표 하드웨어는 착수 시 확인한다. 사진 재현 수준은 기존 화면과 지형 위치를 기준으로 유지하고 변경된 부분은 전후 이미지로 검토한다.
