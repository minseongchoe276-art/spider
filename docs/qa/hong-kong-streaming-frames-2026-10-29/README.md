# 홍콩 외부 타일 프레임 하락과 중복 표면 수정

## 수정 내용

1. **내장 KTX2의 Blob 왕복 제거.** GLTF 이미지 처리 콜백의 Blob 생성이 초기 CPU 프로파일에서 수초의 누적 비용을 차지했다. 파서가 가진 KTX2 바이트를 디코더로 직접 전달한다. 워커 전송용 복사본을 사용해 원래 glTF bufferView를 분리하지 않으며, GLTFLoader의 소스 캐시·샘플러·텍스처 변환·색 공간 처리는 유지한다.
2. **첫 표시 전 셰이더 준비.** `KHR_parallel_shader_compile` 지원 환경에서는 링크 완료를 짧은 비동기 대기로 확인한다. 지원하지 않는 환경·컨텍스트 손실·취소·2초 상한은 정상 렌더링 경로로 돌아간다. 취소된 모델의 준비 중 재질을 해제하며, 취소 후 늦게 도착한 모델에는 프로그램을 만들지 않는다. Three 0.170의 준비 상태 계약을 사용하고, 해당 프로그램 API가 없으면 건너뛴다.
3. **중복 도시 모델 제거.** 사진형 f2 메시에 건물·교량·지면이 이미 있는데 별도의 building/infrastructure 모델이 흰 벽·보행로를 다시 그렸다. 기본 홍콩 구성은 f2 한 레이어로 통일했다. 표시와 충돌이 같은 메시를 사용하므로 색만 숨긴 구조물의 보이지 않는 벽을 남기지 않는다. 기존 사진형 부모 타일 유지와 충돌 복구는 보존한다.

## 실제 플레이 전후 수치

데스크톱 headless Chrome, 1280×800, 기본 품질, 실제 외부 타일. 같은 키보드 점프·이동과 네 방향 카메라 회전 순서로 각각 약 26초를 측정했다. 양쪽 모두 CPU 프로파일러를 켰다. 이전 구성은 테스트 전용 모듈 가로채기로 중복 세 레이어·기존 Blob 경로·표시 시 셰이더 준비를 복원했다. 이후는 수정된 단일 사진형 구성이다.

| 측정 항목 | 이전 | 수정 후 |
|---|---:|---:|
| 원시 RAF 기준 평균 FPS | 36.4 | 47.5 |
| 99백분위 프레임 간격 | 99.9ms | 50.0ms |
| 최대 프레임 간격 | 500.0ms | 83.4ms |
| 50ms 초과 프레임 | 35 | 8 |
| 100ms 초과 프레임 | 7 | 0 |
| Long Task 누적 시간 | 3947ms | 685ms |

프레임 간격은 게임의 delta 상한에 걸린 진단값이 아니라 별도 RAF 관찰값이다. QA 와이어 목표 자동 탐색은 실제 플레이 비용이 아니므로 타이밍 창에서 제외했다. 이후 일반 마우스 입력 경로로 와이어 부착과 이동을 별도 검증했다. 양쪽 모두 점프·와이어 상태에 진입했고 페이지·셰이더 오류는 0건이었다.

**같은 조작 순서의 단일 비교이며, 네트워크·LOD 도착 순서와 실제 이동 거리는 다르다.** 모든 기기에서 같은 FPS나 개선율을 보장하는 벤치마크는 아니다. 앞선 카메라 회전 반복 측정에서도 큰 정지는 줄었지만 작은 지연의 횟수에는 변동이 있었다.

## 화면과 배포용 검증

- `overlap-before.png`, `overlap-after.png`: 동일 장면·카메라·LOD·애니메이션 상태에서 하나의 JS 작업 안에 연속 렌더했다. 기존 중복 구조 레이어의 표시만 바꿨다.
- `production.png`, `production.json`: 별도 검증본의 배포용 빌드. 개발 QA API 없이 일반 키보드 이동·점프와 안내 진행을 확인했다. 중복 3dsd 요청 0건, 페이지·셰이더 오류 0건.
- 실제 GLTF 파서 검사에서 Blob URL 0회, 소스당 디코드 1회, 서로 다른 샘플러·변환·색 공간·실패 진단과 원본 바이트 보존을 확인했다.
- 셰이더 준비의 취소·컨텍스트 손실·무한 대기 방지·중복 해제 방지, 실제 충돌 10개 시나리오·추락 복구·카메라·미니맵 검사를 통과했다.
- 기존 미완료 작업을 제외한 검증본을 사용했다. 검증 소스의 해시는 `VALIDATION.json`에 기록했다.

## 남는 한계

중복 모델의 회색 면 침범·겹침은 제거했다. **원본 사진형 모델 자체의 흐릿한 텍스처와 삼각형 모양의 수목·지형 요철은 일부 남아 있다.** 이 자료를 홍콩 전역의 고품질 모델 재제작이나 모든 화면 깨짐의 완전 제거로 해석하지 않는다. 50~83ms급 순간 지연도 관찰됐으며, 물리 기기 장시간 발열·온라인 전체 권한 검증은 이번 범위가 아니다.

재실행: `npm run test:hong-kong:rendering`. 성능 비교는 `HK_TEST_URL`과 `HK_FRAME_OUT`을 지정하고 `HK_PLAY=1 npm run qa:hong-kong:frames -- optimized`를 실행한다. 이전 구성은 추가로 `HK_OVERLAYS=1 HK_PREPARE=0 HK_DIRECT=0`을 지정한다. 공개 서버에는 테스트용 모듈 가로채기를 적용하지 않는다.
