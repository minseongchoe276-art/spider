## 게임에서 바뀐 점

네온 도심 전체 지도의 건물과 도로를 다시 구분할 수 있다. 도로 선 두께는 세계 좌표 비례 값을 사용하지만 건물·외곽은 화면 픽셀 기준으로 고정한다. 매번 그릴 때 두께를 명시하므로 지도 갱신·다른 지도·작은 화면에서도 이전 캔버스 상태에 의존하지 않는다.

기기 · 연결 진단은 성능·연결·안내·임무·경기 결과가 이 기기에서만 기록된다는 설명을 한국어·영어로 표시한다. 이름·계정·방 코드·좌표·복귀 토큰은 내보내지 않는다. 익명 세션 식별자는 같은 세션의 내보내기를 중복 집계하지 않기 위한 임시 값이며 서버로 전송하거나 영구 저장하지 않는다.

안내 단계별 시간과 닫기, 임무 완료·사용자 중단·다른 임무 선택, 역할별 승패를 실제 전환 시점에 기록한다. 기존 완료 횟수와 마지막 임무 저장은 유지한다. 지원하지 않는 heap은 `null`, 온도·배터리는 미수집으로 표시한다. 표본은 최근 360개, 중단·관찰 이벤트는 각각 최대 256개로 제한한다. 세션 전체 P95는 고정 크기 히스토그램으로 계산한다.

## 버전 식별과 실패 처리

`npm run build`는 `dist/release.json`을 생성한다. `sourceId`는 코드와 공개 모델·모션 등을 함께 식별하고, `codeId`·`assetId`도 별도로 보존한다. `releaseId`는 산출물 파일별 SHA-256에서 계산한다. 비밀 환경 파일을 해시 목록이나 공개 응답에 포함하지 않는다. 환경 설정으로 산출물이 달라지는 경우에는 산출물의 `releaseId`가 달라진다.

Node 프런트 서버와 독립 방 서버의 `/healthz`는 방 서버 구현의 `backendId`와 기대 DB 마이그레이션의 `databaseId`를 제공한다. `databaseId`는 운영 DB에 실제 적용된 스키마의 인증서가 아니다.

`verify:release`는 현재 로컬 소스가 빌드 시점과 다른 경우, 배포 파일이 변조되거나 새 식별 파일이 없는 경우, 방 서버 코드가 다른 경우 실패한다. `--all`은 모든 목록 파일의 실제 HTTP 바이트를 비교하고 생략 시 bootstrap만 비교한다. `verify:device`는 다른 빌드·짧은 활성 시간·프레임/P95 미달 표본을 통과시키지 않는다. 실제 HTTP의 압축 제공 여부는 호스팅별로 별도 확인해야 한다.

## 전송 비용

프로젝트의 빌드 전송 한도는 bootstrap 600,000바이트, 캐릭터 그룹 30,000,000바이트, 압축 전 목록 전체 250,000,000바이트다. 이는 이번 프로젝트의 검사 기준이며 모든 기기의 적정 성능을 보장하는 수치가 아니다.

최종 파일의 역할별 수치·예산은 [릴리스 목록](release-manifest.json)에 기록했다. 캐릭터 그룹은 모든 파일이 첫 프레임 전에 요청된다는 뜻이 아니다. FBX는 컴파일 모션 복구 경로로 유지하며, 원본을 삭제하거나 기능을 낮춰 용량을 맞추지 않았다. 실제 HTTP에서 GLB·FBX를 Brotli/gzip으로 받아 원본과 동일함을 확인했다. 큰 JS 청크 경고는 남아 있다.

최종 bootstrap 그룹의 준비된 압축 합계는 약 0.366MB, 캐릭터 그룹은 약 26.40MB다. 복구용 원본 모션 그룹은 원본 123.10MB에서 준비된 압축 약 29.80MB로 줄었다. 이는 산출물의 사용 가능한 압축 크기 합계이며, 브라우저가 실제로 요청한 전체 전송량이나 모든 호스팅의 전송 방식과 같지는 않다. [실제 바이너리 HTTP 수치](http-delivery.json).

## 운영에서 실제 확인한 것

- 공개 8인 팀전: 정원·팀·시작 보호·지정 상대·아군 공격 거부·상호 피해·쿨다운·탈락·승리·재경기. 공개 3인 개인전도 확인했다. [로그](public-custom.log)
- 공개 2인 개인전: 시작, HP 50에서 같은 ID로 복귀, 이후 탈락과 승리 전달, 임시 방 정리. [결과](public-two.json)
- 운영 Edge 함수: `hong-kong-attack/index.ts`, `_shared/hong-kong-terrain.js`, `hong-kong-attack/deno.json`이 로컬과 SHA-256 일치. [비교](edge-comparison.json)
- 운영 DB: 새 로컬 DB에 실제 마이그레이션을 적용하고 함수 16개를 비교했다. 3개 함수가 없으며 `game_command` 정의 및 일부 서비스 역할 실행 권한이 다르다. [비교](db-comparison.json)
- 없는 운영 함수: `game.sha256_hex`, `public.game_admin_overview`, `public.game_presence_ping`. 관리·접속 상태 관련 마이그레이션과 운영 권한 상태를 확인하고 적용해야 한다. 이 차이를 자동으로 권한 확대하거나 운영 스키마를 변경하는 방식으로 덮지 않았다.
- 공개 사이트에는 새 `release.json`이 없고 방 서버에도 새 fingerprint가 없으므로 동일성 도구가 미통과를 반환한다. 이는 새 도구가 이전 배포를 잘못 합격시키지 않는 결과다. [동일성 검사](release-public.json)

공개 시험은 하나의 검증 기계에서 인터넷을 통해 연결한 임시 클라이언트다. 8명의 사람·다양한 네트워크·실제 브라우저 관전 카메라의 검증과 구분한다. 기존 방을 수정하지 않고 임시 방을 정리했다. DB·Edge는 읽기 전용으로 확인했다.
