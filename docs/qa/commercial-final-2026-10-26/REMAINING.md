# 상업 배포 전 남은 항목과 직접 확인하지 못한 범위

기준일: 2026-10-26 KST. 모바일 HUD 수정과 로컬 기술 검사 완료 여부는 REPORT.md의 최종 집계를 따른다. 이 문서는 상업 출시 승인서가 아니다.

## 실제 확인한 미완료 항목

| 항목 | 확인한 상태 | 배포 전에 필요한 조치 |
|---|---|---|
| 공개 프런트·방 서버 버전 | 공개 release.json 및 서버 식별자 검증 결과는 release-public.json에 기록 | 검증한 최종 파일과 서버를 운영에 반영하고 전체 HTTP 해시·경기·재접속을 재검사 |
| 운영 DB 차이 | 운영 함수·권한을 읽기 전용으로 조회하고 새 로컬 마이그레이션 결과와 비교 | 미적용 compact_city_authority 및 admin_overview 마이그레이션을 운영 상태와 대조해 반영. 지형 데이터 교체가 있으므로 진행 중 경기·복구 방안 검토 후 실행 |
| 관리자 비밀값 | 로컬 최종본은 공통 기본 인증값을 제거. 별도 설정 없으면 관리 기능 잠김 | 호스팅의 GAME_ADMIN_TOKEN 및 DB 관리자 verifier를 운영자 고유 비밀값으로 설정. 프런트 VITE 변수나 저장소에 비밀값을 넣지 않음 |
| 에셋 증빙 | 공개 파일 88개 중 원본·라이선스 해시를 대조한 4개 documented, 84개 needs-review | 모델·모션·변형 텍스처 등의 제작자·원본·허가·표시 조건 자료 연결. 84개는 라이선스 문서·메타데이터·파생 모션을 포함한 파일 수이며 독립된 84개 침해 사례라는 뜻이 아님 |
| 전송·파싱 부담 | 빌드의 500kB 초과 청크 경고 유지 | 실제 배포 호스트의 압축·첫 방문 요청량·저사양 파싱·GPU 업로드 시간 측정. 빌드 용량 예산 통과로 실기기 성능을 대체하지 않음 |

운영 사이트·DB를 자동 배포하거나 운영 스키마·권한·사용자 데이터를 변경하지 않았다. 로컬 후보 빌드와 공개 서비스는 구분한다.

## 직접 확인하지 못한 항목

| 범위 | 이번 검증으로 대신할 수 없는 것 | 필요한 증거 |
|---|---|---|
| 실제 iOS Safari / Android Chrome | Chrome 창 크기 변경과 touchReview는 실제 기기의 터치·웹킷·GPU·OS 시험이 아님 | 기기/OS/브라우저별 첫 방문, 다중 터치, 회전, 앱 전환·복귀 기록 |
| 저사양 PC | 현재 개발 컴퓨터의 통과가 목표 최소 사양 통과를 의미하지 않음 | 목표 CPU/GPU/RAM·해상도를 지정한 실측 |
| 장시간 브라우저 안정성 | 이번 새 버전으로 30~60분 동안 이동·전투·임무를 반복한 기기 시험은 미실행 | 활성 시간·평균 FPS·P95·최장 멈춤·렌더 자원·GC 회복을 포함한 진단과 관찰 |
| 발열·배터리 | 웹 진단의 thermal/battery 미지원 값을 0이나 정상으로 간주하지 않음 | 실기기 관찰·배터리 시작/종료·밝기 저하·브라우저 종료 여부 |
| 신규 사용자 학습 | 안내·임무 규칙 통과가 처음 하는 사람의 이해를 입증하지 않음 | 사전 설명 없는 6단계 안내·5종 임무의 완료/중단/막힘 관찰 |
| 재미·재방문·균형 | 기술 검사로 재미 점수·유지율·역할 승률을 만들 수 없음 | 인원·역할·지도별 여러 실제 경기와 독립 사용자 관찰. 참가자 로그를 독립 경기 수로 중복 합산하지 않음 |
| 다양한 인터넷·8명 실제 플레이 | 로컬 WebSocket 및 지연·메시지 누락 주입은 다양한 회선의 실제 8인 브라우저 경기와 다름 | 서로 다른 회선의 참가·경기·관전·재접속·종료 시험 |
| 하드웨어·접근성·청감 | 실제 패드 기종, 색각·저시력·운동 접근성 사용자, 이어폰·스피커 믹싱 시험 미실행 | 해당 하드웨어 및 사용자 평가 |
| 원본 에셋 권리 | 파일명이나 라이선스 문서 하나로 관련 없는 모델 전체의 권리를 추정하지 않음 | 사용자가 확보한 원본 출처와 상업 이용·재배포 근거 |

이전 2026-10-25의 30분 Node 8인 시험은 과거 서버 시험 기록이다. 이번 최종본의 장시간 브라우저·실기기 합격으로 재사용하지 않았다.

## 운영 보안 진단의 별도 판단

운영 Supabase Security Advisors 원문은 operating-security-advisors.json, 직접 테이블 권한·Realtime 정책 조회는 operating-access-review.json에 보관했다.

- 공개 game_rooms/game_players는 RLS가 켜져 있고 일반 사용자의 직접 SELECT/INSERT/UPDATE/DELETE가 회수돼 있다. 정책이 없다는 INFO를 이유로 전체 테이블 읽기 정책을 추가하지 않았다. [RLS 진단 기준](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy).
- authenticated에 공개된 SECURITY DEFINER RPC 6개는 게임 API 설계와 관련된 WARN이다. 함수의 인증·방 참가자·역할 검증과 실행 권한을 함께 검토해야 한다. 원격 경고를 무조건 제거하려고 권한을 확대하거나 SECURITY INVOKER로 바꾸지 않았다. [함수 권한 진단 기준](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable).
- Realtime의 게스트 접근 경고는 authenticated 게스트와 game_can_receive 토픽 검증을 함께 봐야 한다. 모든 익명 사용자에게 모든 방을 공개한다는 뜻으로 단정하지 않았다. [게스트 정책 진단 기준](https://supabase.com/docs/guides/database/database-advisors?queryGroups=lint&lint=0012_auth_allow_anonymous_sign_ins).
- 유출 비밀번호 보호가 꺼져 있다는 WARN도 남아 있다. 현재 클라이언트의 게스트 로그인 시험과 별개이며, 비밀번호 로그인 운영 범위와 제공 플랜을 확인해 설정해야 한다. 이번에 계정 인증 설정을 변경하지 않았다. [비밀번호 보호 설정 기준](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).

## 다음 출시 순서

1. 최종 로컬 산출물과 소스 해시를 확정하고 운영 반영 범위를 검토한다.
2. 원본 에셋 증빙과 운영자 비밀값을 준비한다.
3. 운영 프런트·서버·DB를 반영한 뒤 전체 파일 및 실제 경기·재접속을 확인한다.
4. 실제 기기·신규 사용자·역할별 경기 관찰을 완료한다.
5. 위 증거를 바탕으로 출시 여부를 판단한다. 자동 검사 수만으로 상업 배포 가능 판정을 내리지 않는다.
