## 판정과 남은 품질 한계

1. **검사한 조건에서 기능상 실패는 재현되지 않았다.** 관절 회전·사지 길이·전환·회복·타격 시점·손목 정렬·접촉·스킨 변형의 코드상 허용오차를 통과했다. 스냅·관절 파손이 모든 상황에서 불가능하다는 뜻은 아니다.
2. **잔여 접지 이동이 있다.** 복합 모션 검사에서 30fps·6.5m/s 질주의 유지된 발 지지 구간 중 프레임 간 발 이동 최대값은 18.7mm였다. 이 검사의 25mm 기준 안이지만 발 미끄럼이 0이라는 판정은 하지 않는다. [측정 로그](motion-combinations.log)
3. **33개가 서로 다른 플레이 기술 33종이라는 뜻은 아니다.** `hook`/`heavy`는 길이와 관절 트랙이 같고, 강공격은 별도 시간 보정(`heavyClipPhase`)과 몸통 표현으로 구별한다. `fall`/`fallVariant`도 관절 트랙이 같다. 기능 오류로 판정하지 않지만, 독립적인 실루엣·동작 다양성을 늘릴 여지는 있다. [동일 트랙 대조](clip-inventory.json)
4. **보존·대체 모션도 빠짐없이 검사했다.** `jumpDown`, `jumpDownVariant`, `injuredIdle`, `rightHook` 등의 등록·보존 클립 검사를 현재 기본 조작으로 모두 발동된다는 의미로 해석하지 않는다. `hook` 역시 일반 입력에 독립 기술로 연결됐다고 판정하지 않는다.
5. **현재 게임의 외형은 하나다.** `CharacterAppearance.setAppearance`는 두 모드에서도 `web` 외형을 사용한다. 브라우저 2회 검사는 두 선택 경로를 확인한 것이며, 서로 다른 외형 2개를 플레이 화면에서 확인했다는 주장은 하지 않는다. 보존된 두 스킨 데이터의 변형 검사와 구분한다.

## 환경 보정과 최신 작업본

초기 58개 실행 중 2개는 모션 검증 후 결과를 쓰는 단계에서 복사본에 기존 QA 출력 폴더가 없어 종료됐다. 폴더 구조를 보완하고 **같은 소스**로 재실행한 `combat-traversal`과 `appearances`는 종료 코드 0으로 통과했다. 최초 기록을 지우지 않았고 [최종 결과](final-results.json)에 최초 실패와 재시도 원인을 함께 보존했다.

고정본 이후 달라진 파일: `src/MobileTraversal.js`, `src/Multiplayer.js`, `src/main.js`. 최신 작업본에서는 모바일 이동·세션 흐름·멀티플레이어·입력 수명주기를 별도로 통과했으며 해당 검사 전후 해시도 동일했다. [최신 작업본 검사](workspace-tail/results.json)

검증 대상은 로컬 코드와 명시된 유한 행렬이다. 실제 인터넷의 지연/패킷 손실, 모든 사용자 입력·지형 조합, 모든 GPU/모바일 기기, 미학적 완성도를 전부 보증하지 않는다. 실제 온라인 배포본이나 외부 서비스는 변경하지 않았다.
