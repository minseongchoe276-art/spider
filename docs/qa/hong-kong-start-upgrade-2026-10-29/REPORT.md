# 홍콩 시작 구역 1차 개선 결과

2026-10-29. 로컬 작업 트리 수정 및 실제 Chrome 입력으로 검증했다. 서비스 배포는 하지 않았다.

## 이번에 직접 적용한 변경

- `src/HongKongStartDistrict.js`: 시작 테라스의 표면을 원본 삼각형에서 분리해 포장 재질로 교체한다. 새 바닥·충돌체를 겹쳐 놓지 않는다. 실제 원점 기준 x -18~18m, z -14~18m에 마스크를 적용하고, 높이 19~22m의 거의 수평인 면만 대상으로 한다. 도로 높이와 수직 벽은 제외한다.
- 일정한 실제 크기의 줄눈, 엇갈린 포장 패턴, 판석별 미세한 색 차이, 화면 미분을 이용한 줄눈 경계 처리를 추가했다. 근거리 포장의 선명도를 원본 사진 해상도에만 의존하지 않는다.
- 첫 화면 검토에서 발견한 삼각형 경계의 단절을 수정했다. 영역을 가로지르는 삼각형도 처리하되 픽셀 단위 마스크로 원본에 전환한다. 원본 Basic 재질 영역은 원래의 비조명 색을 보존해 PBR 조명 차이로 생기는 경계를 줄였다.
- `src/UrbanGroundCity.js`: 지리 원점 변환 후 타일 처리 단계에 연결했다. 타일 로딩 시 원본 표면과 교체 표면을 함께 준비하며, 로더가 교체 재질과 지오메트리를 수거할 수 있도록 한다. 완전히 분리돼 인덱스가 비어 있는 부모 메시는 충돌 수집에서 제외한다. 교체 표면 수와 삼각형 수를 진단에 추가했다.
- 소스 삼각형의 합집합과 월드 좌표를 유지한다. 기존 사진 텍스처 객체·UV를 보존하고, 새 형상·보행 경로·차량 도로를 임의로 만들지 않았다.

같은 폴더에서 별도로 추가 중이던 `HongKongDistrict.js`의 외벽·식생 보강은 보존했다. 외벽을 중복 제작하지 않고 해당 코드와 함께 동작하도록 연결·검증했다. 현재 통합 화면에는 외벽 6면, 창문 1,967개, 프레임 부품 7,868개, 수목 8그루가 진단에 잡힌다. 이 전체 미술 코드를 이번 테라스 변경에서 새로 작성했다는 의미는 아니다.

## 실제 결과

최종 개발 실행에서 시작점은 기존과 같은 (0,20.513,0)이었다. 포장 교체 메시 2개, 삼각형 57개가 표시됐다. 전후 화면은 `comparison.html`과 `reference-before.png`, `after-start.png`에서 볼 수 있다. 카메라 크기는 1280×800이며 타일 로딩 시점과 캐릭터 자세는 완전히 동일하지 않다.

실제 입력 검증:

| 검사 | 최종 관찰 |
|---|---|
| 시작점에서 W 이동·Space 점프·X 카메라 복귀 | 약 5.0초 구간, 약 22.94m 이동, JUMPING 포함 |
| 실제 스트리밍 표면에 마우스 와이어 부착 | SWINGING 상태 확인 |
| 카메라 3방향 회전 | 교체 타일과 화면 확인 |
| 추가 걷기·점프 반복 | 약 31.2초 구간, 약 47.29m 이동 |
| 페이지·셰이더 오류 | 0 |
| production 빌드 일반 키보드 입력 | 이동 목표 0→8m, QA API 없음, 오류 0 |

개발 진입 시간 약 20.62초, production 진입 시간 약 18.86초는 각 1회 관찰값이다. 외부 타일 상태에 영향을 받으므로 로딩 속도 개선율은 주장하지 않는다.

첫 시도는 소스 수정과 겹치는 로딩 중 150초 시간 초과로 끝났다. `interrupted-loading.*`에 증거를 보존했다. 수정된 소스를 유지한 최종 재실행과 production 검사는 통과했다. 중간 시각 검토 결과는 `iteration-1/`에 보존했다.

## 검증

- `node scripts/check-hong-kong-start-district.mjs`: 범위 제한, 경계 삼각형 처리, 원본 텍스처 보존, 동일 월드 삼각형 집합, 중복 처리 방지, ECEF 유사 변환, 실제 Rapier 지지 높이 동일성.
- `node scripts/check-hong-kong-start-webgl.mjs`: 실제 WebGL 셰이더 컴파일·포장 표현. 교체 범위 밖의 Basic 재질 픽셀과 원본 픽셀이 모두 [196,196,196,255]로 같았다.
- `node scripts/check-hong-kong-rendering.mjs`: 기존 렌더링 검사 6개 그룹 통과.
- `node scripts/check-hong-kong-streaming.mjs`: 이동·와이어·LOD 지지면 보존 등 9개 시나리오 통과.
- `node scripts/check-hong-kong-wall-fall.mjs`: 벽 오르기·LOD 보존·추락 복구 검사 통과.
- `node scripts/check-loading-performance.mjs`: 로딩 동시성·스트리밍 카메라·충돌 예산·원본 텍스처 검사 통과.
- `npm run build`: Vite 및 postbuild 통과. 기존 큰 청크 경고는 남는다.
- `node scripts/play-hong-kong-start-upgrade.mjs`: 실제 개발 빌드 플레이 통과.
- `node scripts/play-hong-kong-start-production.mjs`: 별도 preview 서버의 배포 빌드 플레이 통과.

세부 로그와 JSON은 이 폴더에 있다. `source-hashes.json`은 검증 후 관련 소스의 지문이다.

## 남은 문제와 다음 우선순위

1. 시작 테라스 밖의 낮은 광장·주변 외벽은 아직 원본 사진의 흐림과 일부 거친 형상이 남는다. 이번에는 광장 전체 지형을 재제작하지 않았다.
2. 전체 지형/건물 계층의 표면 중복 여부와 원본 수목 충돌은 타일별 검증이 더 필요하다. 별도 외벽·식생 보강의 충돌을 새로 정밀 교체한 작업은 아니다.
3. 프레임 지연은 미해결이다. 최종 짧은 이동 평균 약 55.9FPS/1% low 약 11.5FPS, 추가 이동 평균 약 50.4FPS/1% low 약 15.3FPS였다. 빌드 등 다른 작업과 겹친 로컬 관찰이므로 통제된 전후 성능 비교가 아니다. 안정적인 60FPS 달성을 주장하지 않는다.
4. 최종 캐시는 약 404.6MB로 384MiB 예산을 소폭 넘는 관찰이 있었다. 원본 캐시의 엄격한 전체 메모리 상한을 보장하지 않는다. 다음 엔진 작업은 고정 경로에서 디코드·충돌 생성·GC·그림자 비용을 분리 계측하고, 근거리 타일의 상세도 저하와 순간 지연을 줄이는 것이다.
5. 실제 모바일·15분 장시간·전 지도·온라인 동기화·장거리 운전 검증은 이번 결과에 포함되지 않는다.
