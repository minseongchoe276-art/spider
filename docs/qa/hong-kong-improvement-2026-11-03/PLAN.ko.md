# 홍콩 맵 렌더링·성능 개선 계획

## 목표와 확인된 기준

2026-11-03의 데스크톱 headless Chrome 단일 측정은 평균 47.9 FPS, 99백분위 66.7ms, 100ms 초과 6회였다. 49개 격자 화면에서는 스트리밍 메시 누락이나 셰이더 오류는 없었으나 사진 측량 산지·건물 왜곡과 해안 색 경계가 남았다. 각 수치는 기기와 네트워크에 따라 달라지므로 전체 기기에서 깨짐이나 지연이 전혀 없다고 가정하지 않는다.

## 실행 순서와 완료 조건

1. **재현·측정:** 실제 타일, 동일한 이동·점프·와이어·카메라 회전 시나리오로 기준 프레임, 긴 작업, 주요 CPU 함수를 기록한다. 현재 49개 구역 스크린샷과 결함 목록을 시각 기준으로 활용한다.
2. **프레임 병목:** 프로파일에서 관측된 발바닥 지형 판정의 반복 거리 계산과 할당을 제거한다. 모든 스킨 정점, 지형 높이·경사, 계단 예측과 발 고정 동작은 그대로 유지한다. 기존 수학 결과와 회귀 시나리오를 비교한다.
3. **렌더링 안정성:** 지형·해안 셰이더, 타일 부모/자식 교체, 로딩 실패 복구, 충돌과 와이어 고정면을 검사한다. 실제 화면 근거가 있는 결함만 수정하며 광역 가림막이나 충돌 삭제로 문제를 감추지 않는다.
4. **화질 검토:** 도심·산지·해안의 기존 49개 표본을 대조하고 새 렌더 화면에서 원본 사진 측량 손상과 엔진 오류를 구별한다. 원본 데이터로 복구 불가능한 형상은 위치와 한계를 명시한다.
5. **검증:** 타일·셰이더·충돌·와이어·발 동작 회귀 검사와 빌드를 실행하고 동일 환경의 전후 프레임 측정 및 실제 WebGL 화면을 비교한다. 실패나 미실행 항목, 단일 측정·기기 한계를 기록한다.

## 범위와 한계

사진 측량 원본이 이미 잃은 건물·나무 형상을 전역 셰이더만으로 복구할 수 없다. 정확한 전역 재제작과 다양한 물리 기기·네트워크·장시간 발열 시험에는 별도 자산과 장비가 필요하다. 현 환경에서 가능한 수정과 검증의 완료 상태를 실행 결과에 기록한다.
