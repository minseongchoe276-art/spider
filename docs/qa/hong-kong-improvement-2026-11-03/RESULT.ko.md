# 실행 결과 — 2026-11-03

## 변경

발바닥 지형 판정에서 표면 후보의 계단 높이 계산을 정점마다 반복하지 않고 한 번 계산한다. 가까운 후보 선택은 제곱 거리로 비교하고 동점에서는 기존처럼 뒤쪽 후보를 선택한다. 스킨 정점 수, 지형 탐색, 단계별 IK와 지면 처리 횟수는 바꾸지 않았다.

## 성능 측정

실제 홍콩 타일을 사용하는 Chrome headless, 1280×800, 이동·점프·와이어·네 방향 카메라 동작을 전후 각 1회 측정했다. 양쪽 모두 브라우저/셰이더 오류는 없었다.

| 지표 | 전 | 후 |
| --- | ---: | ---: |
| 측정 시간 | 25.56초 | 25.47초 |
| 평균 FPS | 46.95 | 48.05 |
| 99백분위 프레임 간격 | 66.7ms | 83.3ms |
| 50ms 초과 프레임 | 26 | 24 |
| 100ms 초과 프레임 | 7 | 5 |
| 긴 작업 시간 합계 | 1447ms | 1581ms |

CPU 프로파일의 해당 발바닥 계산 관련 샘플 합계는 약 2646ms에서 925ms로 감소했다. 이 프로파일 합계에는 시작 구간도 포함된다. 프레임 평균은 소폭 올랐지만 99백분위와 긴 작업 합계는 악화됐으므로 이 단일 측정만으로 전체 끊김이 개선됐다고 결론 낼 수 없다. 네트워크·타일 로딩과 플레이 상태가 완전히 동일하지도 않다.

## 검증

- 홍콩 타일 렌더링, 셰이더 준비, 타일 재시도 및 충돌 교체 검사 통과.
- 실제 WebGL에서 외벽 재질과 시작 구역 표면을 그려 셰이더 오류 0건, 기존 표면 바깥 색상 유지 확인.
- 물리·와이어·옥상 올라가기, 확대 보행 전환과 빌드 통과.
- 전투 발 접촉 검사는 잽의 지면 접촉 간격이 약 6.59cm여서 실패했다(기준 3.5cm 미만). 기존 코드의 같은 24 FPS 사례도 정확히 같은 값으로 실패했다.
- 확장 지형 동작 검사 64개 중 31개 통과, 33개 실패. 실패는 발가락 본의 지면 높이 기준이다. 본이 실제 부츠 표면과 일치하지 않을 수 있어 화면상 관통으로 단정하지 않는다. 기존 코드의 평지 30 FPS 두 사례도 같은 실패가 발생했고, 비교한 발 위치·이동·최저 높이 기록은 변경 전후 정확히 같았다. 나머지 실패 사례 모두의 기존 여부는 비교하지 않았다.

## 시각 품질과 남은 일

기존 49개 격자 화면과 이번 플레이 캡처를 검토했다. 기존 보고의 산지·건물 사진 측량 왜곡과 해안 사진 타일 색상 경계는 남아 있다. 이번 작업에서 해당 원본 지형 자산을 교체하지 않았고 모든 화면의 무결함을 보장하지 않는다. 부츠 실제 스킨의 지면 접촉을 포함한 전체 동작별 추가 확인, 원본 자산 보강, 모바일 실기기 및 장시간 시험이 남아 있다.
