# 사용자 설정 경기와 공통 공격 판정

2026-10-20 로컬 구현 및 검수 기록. 운영 배포는 수행하지 않음.

## 제공 기능

- 사용자 설정 → 팀전(1대1 포함) 또는 개인전, 정원 2~8명.
- 기존 방 코드와 새 초대 링크 복사. 초대받은 사람이 같은 도시로 입장.
- 팀전 자동 균등 배정 후 본인이 레드/블루 팀 선택. 팀을 바꾸면 전원 준비 초기화. 빈 상대 팀으로 시작 불가.
- 지형 로딩 완료 후 준비, 방장의 공통 시작 위치 사용, 시작 보호 8초.
- HP 100, 주먹 25 / 거미줄 15, 아군 피해 없음. HP 0에서 탈락·관전. 사용자 설정에서는 구조·부활 없음.
- 마지막 생존자 또는 마지막 생존 팀 승리, 방장 재경기. 명시적 퇴장 시 승리 재평가. 일시 연결 끊김은 기존 30초 복귀 창 유지.

## 공격 판정

`src/AttackRules.js`의 수평 거리·높이·정면 각도 검사를 클라이언트와 WebSocket 서버가 공유한다. 경계값은 이내(포함)이다. 주먹은 타격 모션의 접촉 시점에, 거미줄은 발사 요청 시점에 서버에 제출한다. 서버 수신 당시 저장된 위치로 판정하며, 지연 보상 과거 위치 되감기는 사용하지 않는다.

거미줄은 기존 화면 중앙 NDC ±0.16 / ±0.22 영역을 화면에 표시한다. 몸 중심이 영역과 정면 사거리 안에 들어와야 한다. 공격 요청에 표시된 상대의 ID를 포함하므로 서버가 다른 가까운 사람으로 대상을 바꾸지 않는다. 주먹도 같은 방식으로 타격 대상을 고정한다. 기존 클라이언트는 대상 ID 없는 종전 요청을 사용할 수 있다.

로컬 도시는 생성기의 충돌체, 홍콩은 기존 공식 지형 가시성 판정으로 벽을 검사한다. 서버 확인 전에는 피해나 명중 효과를 확정하지 않는다. 명중은 공격자와 피해자에게 피해량·남은 HP로 표시하고, 빗나감은 사거리·높이·방향·벽·시작 보호·재사용 대기 등 이유를 표시한다. 상대 위치 표시에는 HP와 체력 바, 조준 대상 표시가 있다. 같은 기준이 경찰과 도망자의 경찰 공격에도 적용된다.

## 검증

통과:
- `npm run test:custom`: 실제 로컬 WebSocket 8명/정원 초과, 팀 변경/준비 초기화, 아군 무피해, 지정 대상 고정(가까운 다른 상대 무피해), 양팀 공격, 체력/탈락/팀 승리, 재경기, 개인전, 1대1, 빈 팀 시작 거부, 빗나감 사유, 퇴장 승리, 거리/높이 경계. 조준 영역 밖에서는 피해·쿨다운 요청 없음, 가림·쿨다운 중 이동 와이어 오발 방지.
- `node scripts/check-multiplayer.mjs`: 기존 경찰과 도망자, 준비/역할/체력/시간 종료.
- `node scripts/check-room-server.mjs`: 실제 8명 접속과 공식 홍콩 지형의 명중·벽 차단.
- `node scripts/check-room-reconnect.mjs`: 재접속 및 종료된 경기 좌석 만료.
- `node scripts/check-session-flow.mjs`: 메뉴·도움말 진입과 복귀 7개 사례.
- `node scripts/check-combat-traversal.mjs`: 이동 중 타격, 시작 보호/쿨다운, 서버 확인 명중 효과.
- `npm run build`, `git diff --check`.
- 실제 브라우저 2개로 초대 URL 입장, 자동 팀 배정, 준비, 시작, 양쪽 HP 표시 확인.

`lobby.png`는 최종 대기실 화면이다. 모바일 viewport 요청은 브라우저에서 실제 innerWidth가 바뀌지 않아 모바일 검증으로 간주하지 않았다.

현재 운영 빌드 설정은 전용 WebSocket 주소를 사용한다. 이 구현은 해당 방 서버에 적용된다. 기존 Supabase 전용 방에서는 사용자 설정 생성을 명시적으로 거절한다. 운영 적용에는 새 프런트 번들과 `scripts/rooms.mjs`를 사용하는 전용 방 서버를 함께 배포해야 한다. 실제 인터넷 지연/8명 브라우저 동시 플레이는 이 로컬 검증에 포함되지 않는다.
