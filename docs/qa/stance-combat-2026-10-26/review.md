# 이동 공격과 낮은 자세 검수

검수 기준은 전투 가독성, 무게중심, 발 접지, 관절 제한, 입력 일관성, 전환 시점과 실제 타격 판정의 일치다. 경력이나 ‘무결함’을 주장하는 대신 실제 리그 검사와 렌더 결과를 기록한다.

## 수정한 동작

- 이동 공격: 상체만 공격하던 합성에 잽·스트레이트·훅·강공격·특수공격의 허벅지와 무릎 동작을 추가했다. 타격 구간에서 공격 하체의 비중을 높이고, 준비·회수 구간에서 이동 보폭으로 돌려준다. 기존 지면 IK와 발목 제한을 유지한다.
- C: 앉기 토글. 낮은 골반, 양발 간격, 전방 무릎 굽힘과 작은 이동 보폭을 적용했다. 이동 속도는 최대 1.5m/s다.
- Z: 엎드리기 토글. 골반을 중심으로 몸을 눕히고 목을 들어 진행 방향을 보며, 이동할 때 팔과 무릎을 번갈아 사용한다. 이동 속도는 최대 0.7m/s다.
- X: 기존 C의 카메라 정렬 기능을 이동했다. 설정의 키 변경과 터치 메뉴도 함께 반영했다.
- 낮은 자세에서 공격·회피 입력: 일어서기를 마친 뒤 실행한다. 대기 중에는 스태미나와 타격 판정을 소비하지 않으며 실제 공격 시작 때 온라인 알림을 한 번 보낸다. 취소·일시정지 후 남은 공격을 실행하지 않는다.
- 점프·와이어·벽 이동·낙하·리스폰에서 낮은 자세 상태를 해제한다. 온라인 자세 데이터의 허용 값과 만료 처리를 추가했다.
- 리스폰은 첫 애니메이션 이전에 저장한 원래 뼈 자세로 복원한다. 역바인드 행렬의 위치를 재사용하면 기존 리그의 스케일에 맞지 않아 원래 자세를 직접 보관한다.

앉기와 엎드리기는 현재 서 있는 충돌 볼륨을 유지한다. 낮은 틈을 통과하거나 피격 범위를 줄이는 기능은 포함하지 않는다. 이 기능까지 추가하려면 로컬·서버 충돌 및 피격 판정을 함께 설계해야 한다.

## 확인 중 발견해 고친 문제

- 앉을 때 기존 대기 모션의 긴 앞뒤 보폭 때문에 한쪽 무릎만 꿇던 현상.
- 캐릭터의 좌우 축을 반대로 적용해 양발이 교차하던 현상.
- 엎드린 뒤에도 대기 모션의 다리 굽힘이 남던 현상.
- 정지 자세 캐시에 최종 낮은 자세가 저장되어 다음 프레임에 골반이 다시 내려가던 누적 오차.
- 착지 보정과 낮은 자세 보정이 같은 높이 캐시를 두 번 사용하던 문제.
- 리스폰 후 절차적 관절 회전이 남던 문제.
- 테스트 도구의 오래된 R/T 별칭 횟수, 공중 묘기 기반 클립 기대값, DOM 없는 렌더 루프의 HUD 스텁 누락.

## 재현

- `npm run test:stances`: 24/60/144 FPS에서 실제 리그와 컨트롤러를 검사한다.
- `node scripts/check-strike-steering.mjs`: 이동 방향·카메라 회전·타격 방향·관절 제한.
- `node scripts/check-combat-quality.mjs`, `node scripts/check-combat-feet.mjs`, `node scripts/check-combat-traversal.mjs`: 접촉 타이밍, 발목 연속성, 이동·회피·와이어 연결.
- `node scripts/check-motion-reset.mjs`: 이전 동작과 관계없이 새 캐릭터와 같은 자세로 복귀.
- `node scripts/export-stance-review.mjs`: 실제 `Character.update` 출력으로 9개 모션 타임라인 생성.
- 개발 서버의 `/docs/qa/stance-combat-2026-10-26/review.html`: 정면·측면·후면, 프레임별 재생 검수.

`results.json`은 낮은 자세와 이동 공격 리그 측정치다. `suite-results.json`은 추가 회귀 검사 실행 결과다. 검수 화면은 기록된 리그를 재생하므로 실제 지형 전체를 대신하는 것은 아니다.

## 추가 묘기 제안 — 아직 구현하지 않음

| 우선순위 | 동작 | 적합한 이유 | 구현 조건 |
|---|---|---|---|
| 1 | 스윙 해제 후 공중 360도 트위스트 | 기존 백플립과 회전축이 달라 구분하기 쉽고 와이어 이동의 속도감을 살린다. | 캐릭터만 회전하고 카메라·물리 속도는 유지. 완료 시간보다 지면 도달 시간이 짧으면 시작 금지. |
| 2 | 좌우 사이드플립 | 방향 입력과 동작이 맞아 조작 결과를 읽기 쉽다. | R+좌우 입력을 후보로 사용. 좌우 대칭, 전환 시 관절 뒤집힘, 착지 전 복귀 확인. |
| 3 | 낮은 난간 스피드 볼트 | 장식적인 회전보다 도시 이동에 실제 용도를 더한다. | 장애물 높이·너비·착지 공간·스윕 경로를 먼저 검증. 단순히 캐릭터를 벽 너머로 옮기지 않음. |
| 보류 | 연속 다중 회전·코크스크루 | 화면이 복잡해지고 기존 백플립·착지 회복과 역할이 겹칠 수 있다. | 기본 동작의 실플레이 판독성과 착지 안정성을 먼저 확인. |

첫 추가는 360도 트위스트를 권한다. 기존 R 백플립은 유지하고 방향 입력으로 새 동작을 고르는 방식이 단축키 부담이 적다. 이 제안은 현재 게임 코드와 이동 구조를 근거로 한 설계 판단이다.
