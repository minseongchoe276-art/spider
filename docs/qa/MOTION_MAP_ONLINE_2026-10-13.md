# 모션·3D 지도·실제 온라인 후속 검증

검증 완료일: 2026-10-13, Asia/Seoul. 로그 폴더는 작업 시작일인 10월 12일 이름을 유지한다.

## 발견한 문제와 수정

| 문제 | 수정 |
|---|---|
| 미니맵에서 높이가 색으로만 표현됨 | 실제 도시 삼각형을 별도 직교 카메라로 렌더링. 옆면과 지붕, 경사진 지형을 표시 |
| 홍콩 타일의 경계 상자가 하나의 건물처럼 보임 | 경계 상자 대신 실제 타일 메시 사용 |
| 본 화면 밖 타일이 지도에서 빠짐 | 지도 카메라도 타일 선택에 등록. 220m 범위의 낮은 해상도로 주변 타일 요청 |
| 지도용 타일이 본 화면에도 불필요하게 그려질 수 있음 | 다중 카메라에서 메시별 프러스텀 컬링 복원 |
| 지도에 온라인 친구가 표시되지 않음 | 실제 높이와 위치에 팀 색상 마커 추가. 사망·퇴장 마커 제거 |
| 상대가 모션 없는 캡슐로 표시됨 | 로컬 모델과 클립을 공유하되 스켈레톤과 믹서는 독립 복제 |
| 상대 스윙·줄 놓기·벽 자세·전투 자세가 전달되지 않음 | 인증된 이동과 함께 모션, 속도, 손별 부착점, 벽·옥상 진입·전투 정보를 전달 |
| 상대 이동 보간이 FPS에 따라 다름 | 지수 보간과 보간된 이동 속도에 따른 발걸음 사용. 오래된 자세와 줄 해제 |
| 새 탭의 로그인 변경이 다른 탭의 Realtime 토큰을 바꿈 | 탭별 인증 저장 키로 GoTrue 알림 분리. 새로고침에서는 같은 키 유지 |
| 재접속 때 인증 클라이언트와 타이머가 중복됨 | 클라이언트 재사용, 연결 종료 때 타이머·채널 정리 |
| 준비·시작 요청 및 늦은 방 응답이 순서와 상태를 꼬이게 함 | 제어 요청 직렬화. 떠난 방의 응답 무시. 채널 교체 전 이전 채널 분리 |
| 재접속 시 이전 `playing` 값 때문에 경기 진입을 건너뜀 | 연결 종료 시 마지막 단계 초기화. 로딩 대기 타이머도 단일화·취소 |
| 모델을 다 읽기 전에 상대를 복제하면 영구 대체 모델이 남음 | 캐릭터 로딩 완료 후 상대 생성 |
| 자유 플레이 시작 시 친구가 옆으로 떨어져 보여 서로 찾기 어려움 | 시작 방향을 공통 중심으로 정렬 |
| 주먹이 준비 동작 때 즉시 피해를 줌 | 모션의 타격 구간에서 한 번만 서버 공격 요청. 취소된 동작은 요청 취소 |
| 거미줄 피해 방향이 실제 조준과 다름 | 조준 NDC와 카메라의 광선 방향 사용 |
| 건물 뒤 상대에게 공격 요청을 보냄 | 가장 가까운 판정 대상까지 도시 광선으로 가림 검사 |
| 문서의 온라인 방식·클립 수가 현재 구현과 다름 | Supabase 운영 방식과 39개 클립, 26개 원본으로 수정 |

## 검증과 증거

- `npm test`: 성공. 39개 전체 모션, 117개 FPS 조합, 16,183프레임을 검사했다. 기존 실제 리그·지면·계단·옥상·충돌·전투·웹·홍콩 스트리밍 회귀 검사도 통과했다.
- `check-remote-motion.mjs`: 실제 GLB를 복제해 30/60/144 FPS에서 이동, 독립 관절, 스윙, 왼손 줄 표시와 해제, 오래된 자세, 퇴장 자원 정리를 확인했다. 방 응답 지연, 채널 교체, 인증 키 분리, 조준 방향, 가림, 타격 시간, 동작 취소도 검사했다.
- `check-minimap.mjs`: 높이 투영, 동·북 방향, 중첩 모델 변환, 실제 삼각형 공유, 주변 메시 선택, 주 도시 지오메트리 보존을 확인했다.
- `npm run build`: 성공. 큰 번들 경고는 남아 있다. 홍콩 타일 1.1 확장에 대한 라이브러리의 제한 지원 경고도 표시된다. 현재 확인한 타일·텍스처·충돌은 정상이다.
- 운영 Supabase에 서로 다른 익명 계정으로 접속해 방 생성/참가, 비공개 채널, 준비·방장 제한, 시작, 양방향 이동, 인증된 스윙·손별 줄 자세, 8초 공격 제한, 타격 전달, 방 복귀, 방장 퇴장, 재경기, 자유 플레이를 검증했다. 테스트 방은 퇴장으로 정리했다.
- 브라우저 두 탭에서도 독립된 플레이어 이름, 준비 상태, `2명 접속`, 상대 스파이더맨과 지도 마커를 확인했다. 새로고침 후 같은 방·플레이어로 복귀했다.
- 로컬 실제 화면에서 양발 발목 높이는 95.822m, 지지면은 95.711974m였다. 발목과 발바닥 사이 11cm 여유와 일치한다. 화면 진단 값은 `browser-runtime.json`에 저장했다.
- 실제 홍콩에서도 도시 준비 완료, 실제 지형 메시와 미니맵, 텍스처 디코딩과 지면 접지를 확인했다. 지도 카메라를 타일 선택에 등록한 최종본에서도 준비 완료와 127개 지도 메시, 147개 충돌 메시, RGB 텍스처 3개, 양발 접지를 확인했다. `hong-kong-runtime.json`과 `hong-kong-3d-map.jpg`에 저장했다.

- 최종 일반 화면은 `online-3d-map.jpg`에 저장했다. 상단 2명 접속, 두 스파이더맨 모델, 하단 입체 지도와 친구 마커를 확인했다.
- 다른 채팅의 동시 수정으로 개발 서버가 재시작되어, 최종 브라우저 검사는 08:45경 소스 복사본으로 고정했다. `verified-snapshot.json`은 검사한 주요 파일의 해시를 기록한다.
- 방 재입장·만석 동일 방 복귀·중복 입장·만료된 멤버십 회귀 검사도 통과했다.

증거 폴더: `docs/qa/motion-map-online-2026-10-12/`.

## 범위와 남는 한계

프런트엔드는 현재 작업 폴더와 로컬 브라우저에서 검증했다. 이번 작업에서 프런트엔드 공개 배포는 하지 않았다. 모션 전달용 Supabase RPC는 운영 프로젝트에 적용했다.

가림 검사는 정상 클라이언트의 공격 요청을 차단한다. 서버가 홍콩 지형 전체를 재현하는 부정행위 방지 시스템까지 구현한 것은 아니다. 실제 타일의 로딩 시간과 프레임률은 연결·기기·동시에 열린 게임 탭 수에 영향을 받는다. 모든 기기와 모든 인터넷 환경에서 오류가 없음을 증명하는 검증은 아니다.

`?hongKongAudit=1`에서 실제 리그 발 위치, 지원 지형, 상대 모션과 지도 메시 수를 읽을 수 있다. 일반 플레이에서는 검사 패널을 표시하지 않는다.
