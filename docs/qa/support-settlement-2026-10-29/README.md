# 방향 전환·전투 정지 접지 수정 — 2026-10-29

방향 전환 후 정지와 전투 이동 후 정지에서 남던 발바닥 틈을 실제 부츠 스킨 기준으로 수정했다. 앞선 공중 보행·스트레이트 뒷발 접촉 수정도 함께 커밋 범위에 포함한다.

## 원인과 변경

- 발가락 뼈의 중심점이 실제 부츠 밑창보다 낮은데도 그 점을 바닥 관통 제한에 포함했다. 전투 뒷발에서 뼈는 바닥에 닿고 실제 부츠는 약 2cm 떠 있었다. 뼈는 지형 탐색 위치로 유지하고, 바닥 간격은 렌더링되는 부츠 정점으로 계산한다.
- 접지 보정이 위쪽으로만 이동해 최종 관절 보정 후 남은 작은 틈을 없애지 못했다. 지지 중인 발의 6cm 미만 틈을 시간에 비례해 아래로 좁힌다. 공중 동작과 높은 발 들기, 지붕 인계는 이 경로에서 제외한다. 계단 앞 발끝 들어 올리기와 바닥 관통 방지는 유지한다.
- 발목 방향 보정과 발바닥 보정에서 서로 다른 다리 도달 거리 제한을 사용했다. 두 경로를 99.5%로 맞춰 뼈를 늘리지 않고 무릎의 완전 펴짐도 피한다. 기존 발목·발가락 관절 각도 제한은 유지한다.
- 정지 자세 캐시는 접지 간격이 수렴한 뒤 재사용한다.
- 홍콩 맵의 오래된 충돌 LOD는 새 표면이 캐릭터 발밑 전체를 덮는지 확인한 뒤 교체한다. 낮은 상세 지형 위에 보이지 않는 옛 바닥이 남는 문제와 스트레이트의 뒷발 접촉 해제를 함께 수정한다.

## 실제 플레이 검증

작업 폴더의 다른 미커밋 변경을 제외하고 **커밋할 파일만 추출한 환경**에서 게임을 실행했다. 기본 도시와 홍콩 맵 각각에서 키보드로 이동·방향 전환·전투 이동 후 정지를 수행했다. 마지막 정지 표본 4개 × 양발의 최대 간격은 아래와 같다.

| 장면 | 물리 지면과 실제 밑창 간격 | 보이는 지면과 실제 밑창 간격 |
|---|---:|---:|
| 기본 도시 방향 전환 후 정지 | 약 3mm | 약 3mm |
| 기본 도시 전투 이동 후 정지 | 약 3mm | 약 3mm |
| 홍콩 방향 전환 후 정지 | 약 3mm | 약 3mm |
| 홍콩 전투 이동 후 정지 | 약 3mm | 약 3mm |

개별 표본은 `play.json`, 실행 결과는 `play.log`에 보관했다. 검사 기준은 양발 각각 물리 간격 -3~8mm, 표시 지형 간격 -5~12mm다. 목표 간격 3mm는 지면 깜박임·메시 관통을 피하기 위한 여유다. 달리는 중 의도적으로 들어 올린 발을 땅으로 끌어내리지는 않는다.

별도 실제 플레이에서는 일반 이동·전력 질주·점프·공중 상태·착지 후 정지·전투 전환·차량 탑승 및 하차를 확인했다. `journey-summary.json`과 `journey.log`에 상태와 발 측정값을 보관했다. 차량 이동 거리는 이번 승하차 검증의 합격 기준에 포함하지 않았다.

## 회귀 검사

- `node scripts/check-support-settlement.mjs`: 실제 웹·전투 외형, 24/60/144 FPS, 평지와 두 경사 방향. 정지 전투의 양발, 주입한 작은 접지 오차의 수렴, 관통 방지, 들어 올린 발 보존을 18개 조건에서 검증한다. **수정 전 HEAD에서는 전투 뒷발이 떠서 실패**함을 별도로 확인했다 (`baseline-regression.log`).
- `node scripts/check-review-ground-contact.mjs`: 웹에서 공격·방어로 전환하는 54개 조건의 실제 스킨 간격·발 기울기·정지 드리프트.
- `node scripts/check-silk-gait.mjs`: 24/30/60/144 FPS의 걷기·달리기·경사·방향 전환·점프·지붕 인계 및 기존 실 표현 검사. 발가락 뼈 좌표는 진단값으로 기록하고 실제 부츠 메시의 관통·접지·관절 속도를 검증한다.
- `node scripts/check-hong-kong-streaming.mjs`: 기존 스트리밍·웹 동작과 90cm 낮은 상세 바닥 교체, 불완전한 대체면에서 옛 지지면 보존.
- `node scripts/check-hong-kong-wall-fall.mjs`: 벽타기·지붕 인계·LOD 유실·추락 복귀.
- `node scripts/check-vehicle-slopes.mjs`: 실제 Rapier 지형에서 경사·정상부·내리막·후진·벽·도로 유실.
- `npm run build`: 커밋 대상만 추출한 환경의 모션 생성·프로덕션 빌드·자산 후처리.

이번 검증은 로컬 Chrome과 자동 리그/물리 검사 범위다. 모든 홍콩 좌표·실제 모바일 기기·모든 네트워크 지연 조건을 전수 검증한 결과는 아니다.

최종 회귀 결과: 접지 18개·전투 전환 54개·경사/동작 전환 71개·스트리밍 10개·벽/추락 4개 통과. 차량 경사 검사와 프로덕션 빌드도 통과했다. 분리된 환경의 로그는 `isolated-*.log`, 검사 결과 요약은 `validation.json`에 보관했다.
