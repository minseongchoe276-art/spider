# 홍콩맵·그래픽 개선 진단 및 제작 계획

기준일: 2026-10-29. 범위: 현재 작업 트리의 홍콩맵 코드, 기존 실측 원본과 화면, 별도 신규 로컬 브라우저 관찰. 이번 산출물은 진단·실행 계획이며 게임 구현 변경은 하지 않는다. 기존 미커밋 변경을 포함한 현재 상태를 검토했다.

## 결론

가장 먼저 해결할 것은 근거리 원본 형상과 표면 품질이다. 화면 전체에 효과를 더하거나 LOD 수치만 높이는 방식으로는 늘어난 벽 사진과 각진 수목·지형을 복구할 수 없다. 시작점 주변의 대표 구역을 정밀 제작하고, 스트리밍·충돌·조명을 함께 검증한 뒤 확장한다.

## 우선순위와 실행 단계

### 1. 재현 가능한 기준 장면 확보 — P0, 개발/QA

시작점, 보도, 교차로, 옥상, 조경, 고속 스윙 경로의 6개 관찰점을 만든다. 각 관찰점에 위치·카메라·해상도·품질·빌드 지문·대기 시간·활성 타일 URL/ID를 저장한다. 차가운 캐시와 따뜻한 캐시를 나눠 같은 60초 경로를 각 5회 측정한다.

저장할 값: 프레임 시간 p50/p95/p99, 긴 프레임, 요청/디코드/파싱/충돌 생성 시간, 타일 캐시·JS heap, 오류, 표면 높이와 법선. JS heap이나 타일 캐시를 총 GPU 메모리라고 표기하지 않는다.

완료: 화면 결함마다 좌표·카메라·타일 ID·재현 단계가 있는 이슈 목록과 동일 조건 기준 이미지가 존재한다.

### 2. 근거리 형상과 표면 정리 — P0, 테크니컬 아트/맵 개발

시작점 주변 80–120m를 첫 제작 범위로 한다. terrain/building/infrastructure를 한 계층씩 숨겨 결함 타일을 특정한다. 사진 지형의 건물과 구조물 모델이 겹치는 곳은 표면 단위로 소유권을 정한다. 보강 모델은 해당 영역의 원본을 실제로 제거·클리핑한 뒤 넣는다. 단순히 위에 덮어 z-fighting과 이중 충돌을 만들지 않는다.

보도·계단·난간·입구·옥상 가장자리부터 정확한 형상으로 교체한다. 수목은 식별한 식생 영역만 교체한다. 녹색 픽셀 일괄 분류는 피한다. 타일 좌표 변환과 배치 원점은 UrbanGroundCity의 원점을 공유한다.

충돌 전환: 원본 활성 → 대체 렌더/충돌 준비 → 둘을 같은 프레임에 전환 → 원본 충돌 해제. 타일 재로딩·퇴거 시에도 소유권을 유지한다. 실패하면 기존 지지면을 유지한다.

완료 목표: 대표 경로의 추락·유령벽·이중 표면 0건, LOD 전환 시 정지 플레이어 지지 높이 변화 10cm 이내. 의도한 턱/계단은 별도 표기한다. 장거리에는 그대로 적용됐다고 주장하지 않는다.

### 3. 홍콩 거리의 재질·생활 디테일 — P1, 환경 아트

가까운 외벽은 건물 유형별 재질, 실제 크기의 창틀·상점 입면·간판·실외기·옥상 설비로 제작한다. 같은 창문 무늬의 전 건물 반복을 줄인다. 0–30m는 형상/재질 디테일, 30–120m는 단순화 모델, 원거리는 기존 타일을 기본안으로 삼고 실측으로 경계를 조절한다.

에셋과 배치는 instancing/atlas를 검토하고 이동·차량 출구·와이어 연결을 막지 않도록 한다. 사용한 에셋의 라이선스와 출처를 기록한다. 개인 정보나 비밀 키가 포함된 요청 URL은 로그에서 제거한다.

완료: 동일한 6개 기준 장면에서 텍스처 늘어짐·깜박임·지면 침투·부유 소품이 없고, 대표 거리에서 보도/차도/출입구가 구분된다.

### 4. 조명·접지감 일관성 — P1, 렌더링 개발/아트

먼저 Basic/Standard와 구운 조명의 비중을 분류한다. 촬영된 사진을 무조건 PBR로 바꾸거나 전역 노출을 올리지 않는다. 중성 기준 재질로 캐릭터·차량·보강 건물의 밝기와 거칠기를 맞춘다. 사진 속 그림자 방향과 태양 방향의 충돌을 기준 장면에서 확인한다.

접촉 그림자는 캐릭터·차량 주변의 제한된 범위에서 비교한다. SSAO/후처리는 단계 2와 성능 계측 후 별도 A/B 실험으로 평가한다. 변경은 홍콩 전용 프로필로 제한하고 low 프리셋의 비용을 따로 확인한다.

완료: 밝은 면의 디테일 소실과 그림자 속 캐릭터 실루엣 소실이 없고, 그림자 이동 시 떨림·이중 명암이 기준 영상에 없다.

### 5. 스트리밍과 프레임 지연 — P1, 엔진 개발

단계 1의 측정으로 병목을 나눈 후 요청 동시성, 디코드 워커, 충돌 작업 예산을 하나씩 조절한다. 플레이어 진행 방향과 근거리 지지면을 우선하며, 카메라 회전 때 구조물 표시가 굶지 않게 한다. 공유 캐시의 계층별 점유·거절 요청·errorTarget 변화를 함께 기록한다.

낮은 errorTarget 또는 큰 캐시를 단독 해법으로 채택하지 않는다. 거리 falloff는 기존 실험에서 시작 높이가 바뀐 회귀가 있어 재도입 시 충돌 회귀 검증이 선행돼야 한다. 신규 타일 실패 시 준비된 부모/지지면을 유지하고, 명시적 재시도와 기존 로딩 오류 흐름을 보존한다.

제안 성능 목표(현재 달성 주장 아님): 선정한 기준 데스크톱 1080p balanced에서 60초 경로 p95 ≤20ms, p99 ≤33.3ms. 실제 중급 모바일은 low에서 p95 ≤33.3ms를 1차 목표로 한다. 기기·브라우저·해상도 명시 전에는 합격 판정을 하지 않는다. 로딩 목표는 5회 이상 cold/warm 측정 후 네트워크 조건별로 확정한다.

## 작업 규모와 결정이 필요한 사항

단계별 순서는 기준 측정 → 대표 구역 형상 교체 → 재질/거리 디테일 → 조명 → 병목 수정 → 반복 검수다. 인원·에셋 조달·원본 수정 가능성 확인 전 일정 확약은 하지 않는다. 우선 한 대표 구역을 완료해 실제 제작 소요를 산출한다.

확정할 항목: 목표 기기 등급, 사진 재현과 스타일화 중 미술 방향, 원본 타일의 선택적 클리핑 가능성, 에셋 예산. 이 결정 전에도 기준 측정과 결함 타일 식별은 진행 가능하다.

## 신규 관찰 결과

별도 Chrome 1280×800, 홍콩 solo 진입 후 15초 추가 대기한 결과를 `fresh-observation.json`과 `fresh-start.png`에 저장했다. 시작 위치는 (0,20.513,0), 지형/건물/기반 시설 메시 수는 57/29/3, draw calls 113, triangles 281,992, JS heap 약 591MiB, 페이지 오류 0이었다. 한 시점의 관찰이며 평균 성능 수치는 아니다.

지형 errorTarget은 기본 10에서 약 13.40, 건물은 기본 12에서 약 16.08로 완화됐다. 요청 거절은 각각 34/1로 기록됐다. 따라서 캐시 압력에 의한 근거리 상세도 저하는 현재 실행에서도 확인됐다. 다만 이것만으로 화면의 모든 흐림 원인을 캐시로 단정하지 않는다.

신규 화면에서도 왼쪽 고층 외벽 사진의 늘어짐, 오른쪽의 큰 단색 외벽, 근거리 표면 경계의 거친 접합을 확인했다. 기존 final-city.png의 각진 조경 돌출부는 다른 시점/시야의 증거이며 신규 시작 화면에서 같은 돌출부를 재현했다고 주장하지 않는다. 실제 중복 표면 여부는 단계 2의 계층 분리 관찰로 확정한다.
