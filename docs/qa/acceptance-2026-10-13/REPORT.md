# 최종 합격 프롬프트 실행 — 2026-10-13

## 최종 판정: FAIL

[작성한 프롬프트](PROMPT.md)를 현재 게임에 적용해 실제 수정과 검증을 수행하고, `npm run verify:acceptance`로 합격 조건을 실행했다. 정상 검사 통과와 전체 게임 합격을 구분한다. 홍콩 경쟁전의 서버 독립 명중 판정이 실패하여 **완벽 또는 최종 합격으로 판정하지 않는다.**

자동 실행 결과와 소스/모션/모델 해시는 [execution.json](execution.json)에 있다. 이 명령은 필수 검사 하나라도 실패하거나 필수 운영 증거가 없으면 종료 코드 1을 반환한다. 운영 확인 기록은 30분이 지나면 다시 확인해야 하며, 검사 중 소스와 모델이 바뀌어도 실패한다.

## 수정 및 운영 적용

1. **운영 반복 순간이동 허용 수정:** 매 패킷마다 20m 여유를 새로 주던 조건을 제거했다. 플레이어 행에 누적 이동 예산을 저장하고 수용된 이동만 비용으로 차감한다. 거부된 요청은 위치와 예산의 기준 시간을 바꾸지 않는다. 기존 위치 correction을 반환한다.
2. **절차적 도시의 메뉴/비활성 피해 면제 수정:** 공격자 위치의 신선도는 검사하되, 방어자가 이동 메시지를 멈췄다는 이유로 마지막 확정 위치에 대한 피해를 거부하지 않는다. 홍콩의 별도 명중 확인 문제는 아래 실패 항목으로 남아 있다.
3. **연속 구조 검증:** 두 패킷의 시각 차이만으로 3초 구조가 완료되지 않도록 500ms보다 큰 이동 갱신 공백이 생기면 구조를 다시 시작한다. 절차적 도시에서는 벽 가림도 검사한다.
4. **중복/인접 탈출 목표:** 동일하거나 25m 미만으로 인접한 목표를 제거한다. SQL과 JavaScript가 같은 결과를 내는지 검사했다.
5. **DB 행 잠금 순서:** 자기 플레이어 → 방 → 상대 플레이어로 잠그던 경로를 방 → 플레이어 순으로 통일했다. 서로 공격/이동할 때 상대 행을 기다리며 생길 수 있는 교착 경로를 줄였다.

운영 적용 파일: [verified_movement_and_continuous_rescue.sql](../../../supabase/migrations/20261013052333_verified_movement_and_continuous_rescue.sql). 실제 Supabase 프로젝트 `spider`에 적용 성공했다. 적용 직전 진행 중인 경기는 0개였다. 데이터 삭제나 기존 사용자 권한 확장을 수행하지 않았다.

운영 함수와 격리 PostgreSQL에서 테스트한 함수의 `prosrc` MD5는 모두 `7462b243748cb2d41bbd7b04c096d1c0`이었다. 운영 확인에서 기존 패킷별 여유 조건과 방어자의 이동 중단 면제 조건이 제거됐으며, 기존 비공개 스키마/테이블 접근 제한과 authenticated RPC 권한이 유지됨을 확인했다. [운영 확인](operating-verification.json).

복구가 필요한 경우 운영 변경 전 [함수 정의](operating-command-before.sql)를 이용할 수 있다. 새 열과 비공개 보조 함수는 데이터 삭제 없이 남겨도 기존 함수와 호환된다. 기존 정의로 되돌리면 이번에 수정한 이동/구조 문제도 다시 생기므로 복구 후 재검증해야 한다.

## 실제 검증

- 전체 게임·모션 검사와 빌드 통과. [게임 검사](tests.log), [빌드](build.log).
- Docker나 유료 클라우드 branch 없이 [embedded-postgres](https://github.com/leinelissen/embedded-postgres)를 이용해 격리 PostgreSQL 17.10을 실행했다. 테스트가 끝나면 임시 서버와 데이터 디렉터리를 정리한다.
- 실제 SQL 함수, 별도 연결, 역할 제한, 트랜잭션, 동시 요청으로 **16개 검사**를 통과했다. 2~8명 경기, 역할/시간, 반복 순간이동, 정상 48m/s 및 500ms 지연, 거부 후 예산 보존, 롤백, 병렬 이동, 연속 구조, 공격/이동 동시 요청, 메뉴 피격, 목표 중복을 검사했다. [SQL 결과](postgres-results.json), [로그](postgres.log).
- 로컬 SQL 검사의 Auth 사용자 식별과 Realtime 네트워크 송신은 테스트용 대체 구현이다. PostgreSQL 계산·잠금·권한·트랜잭션 자체를 대체한 것은 아니다.
- **실제 운영 Supabase RPC:** 두 독립 게스트의 방 생성·참가, 준비 거부, 유효 arena, 경기 시작, 경계 correction, 복귀, 직접 테이블 접근 거부를 확인했다. 테스트 방 참가를 정리하고 세션을 종료했다. [운영 RPC 검사](operating-rpc.log).
- Security Advisor는 적용 전후 4개로 동일했으며 새로운 알림이 추가되지 않았다. 기존 RLS 정책 없음 알림을 없애려고 테이블 접근 권한을 열지 않았다. [전](security-advisors-before.json), [후](security-advisors-after.json), [함수 권한 공식 문서](https://supabase.com/docs/guides/database/functions).

## 합격을 막는 재현된 결함

**SEC-01 / P1: 홍콩 경쟁전의 피해자 클라이언트가 피해를 거부할 수 있다.**

독립 로컬 서버에서 같은 유효 공격을 보냈을 때 피해 확인을 무시하면 HP 100, `clear:false`를 보내도 HP 100, `clear:true`를 보내야 HP 75가 됐다. 이번 운영 함수 확인에서도 해당 분기는 남아 있다. 운영 참가자에게 공격하거나 공격 악용 검사를 수행한 것은 아니다. [재현 결과](security-final.log).

해결을 위해 공식 홍콩 지도에서 서버가 직접 geometry를 읽는 탐색 구현도 실행했다. 플레이어가 제출한 mesh 없이 3개 지도 층에서 389개 mesh, 698,550개 삼각형을 읽었다. [탐색 로그](hong-kong-geometry-probe.log), [탐색 코드](../../../scripts/probe-trusted-hong-kong.mjs).

하지만 이 탐색은 운영 명중 서비스와 연결된 구현이 아니다. 검증된 지역 전체의 충돌 데이터 준비 상태, 지도 버전/LOD 일치, 서버의 독립 시야 검사, 인증된 최종 피해 반영, 캐시/메모리/지연 검사가 추가로 필요하다. 지형 일부를 읽었다는 사실만으로 운영 서버 판정이 구현됐다고 취급하지 않는다. 시간 초과를 무조건 명중으로 바꾸거나 홍콩 기능을 제거해 합격시키지도 않았다.

## 해석

프롬프트 작성과 실행, 재현된 이동·구조·목표·잠금 결함 수정 및 운영 적용은 완료했다. **요청한 전체 게임의 완벽 판정은 아직 충족하지 못했다.** 실제로 남은 P1이 있기 때문이다. `execution.json`의 FAIL을 PASS로 바꾸거나 미해결 검사를 제외하지 않는다.
