# 홍콩 경쟁전 서버 판정 구현 조건

이 문서는 남은 SEC-01을 PASS로 표시하기 위한 변경 계획이다. 계획 또는 지형 탐색 코드를 운영 구현으로 취급하지 않는다.

## 준비된 부분

- 공식 지도 3개 층을 서버에서 geometry만 읽는 탐색 코드가 실행됐다.
- 판정 인터페이스 `TrustedTerrain.visibility(from,to)`는 CLEAR/BLOCKED/UNKNOWN을 구분한다. 검증된 지형 범위와 버전이 없거나 범위를 벗어나면 UNKNOWN이다. UNKNOWN이나 무응답을 명중으로 바꾸지 않는다.
- 합성 벽 fixture에서 벽 관통 차단, 명확한 시야, 버전 없는 geometry, 범위 밖 요청, 잘못된 좌표를 검사했다.

## 운영 연결에 필요한 변경

1. 서버가 공식 지도에서 room arena 전체의 지형을 준비하고, 사용한 출처·버전·좌표 변환·LOD·범위·누락/오류 여부를 기록한다. 플레이어가 보낸 mesh나 clear 값을 사용하지 않는다.
2. 서버가 준비됐다는 인증된 상태가 있어야 경쟁전을 시작한다. 지도 로딩 실패는 사용자에게 표시하고 준비를 재시도한다. 이미 시작한 경기에서 지형 장애가 발생했을 때의 중단/재시작 규칙을 정의한다.
3. 공격자의 JWT 또는 서버 소켓 ID로 신원을 확인하고 방 참가·역할·시작 보호·거리·방향·재사용 시간을 검증한다. 서버가 확정한 두 플레이어의 위치를 이용해 시야를 검사한다.
4. DB의 피해 확정 함수는 판정 서비스의 서버 자격으로만 호출할 수 있어야 한다. 공격/피해자의 public RPC로 clear를 전달하는 기존 경로로는 피해를 확정할 수 없도록 한다.
5. 판정 서비스는 요청 ID, 중복/순서/만료, 경기 종료/재경기, 탈락/구조, 플레이어 퇴장과 동시 요청을 검증한다. 늦은 요청이 다음 경기에 피해를 주지 않아야 한다.
6. 원격 mesh 생성·삭제, 메모리 상한, 여러 방의 캐시, cold start, 지도 변경, 실패 복구 및 정상 공격 지연을 실제 운영 대상에서 측정한다.
7. 2~8명 정상 경기와 공격자/피해자의 변조, 벽/층/옥상 가림, 이벤트 무시, clear 위조, replay, 메뉴/비활성 창, 재접속을 검사한다. 기존 실패 진단을 통과시키고 새 회귀 검사에 포함한다.

## 운영 방식 선택

- **상시 Node 게임 서버:** 현재 WebSocket 서버와 Three 기반 지형 코드를 함께 사용할 수 있다. 지형 캐시 유지에 적합하며 서버 용량·호스팅·Supabase와의 인증된 연동 구성이 필요하다.
- **기존 Supabase 안의 판정 서비스:** Edge Function과 서버 전용 지형 저장/캐시를 사용할 수 있다. 실행 시간·메모리·cold start와 Storage/DB 비용을 확인해야 하며, 준비 단계와 실제 공격 시점의 조회를 분리해야 한다.

어느 방식도 피해자의 확인을 독립 서버 판정으로 이름만 바꾸는 것으로 완료하지 않는다. 유료 리소스 생성은 대상·가격·검증된 구현을 제시하고 승인받은 뒤 수행한다.
