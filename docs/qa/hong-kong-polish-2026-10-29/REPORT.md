# 홍콩 맵 분석·렌더링 개선 결과

2026-10-29. 실제 외부 홍콩 3D Tiles와 로컬 Chrome으로 검증했다. 원본 사진의 저해상도나 손상된 지오메트리를 모두 복원한 작업은 아니며 GTA 수준의 완성을 의미하지 않는다.

## 1. 분석과 발견

도시는 같은 지리 원점을 사용하는 f2 사진 지형, 건물, 기반 시설의 세 계층이다. 사진 지형에도 건물 모습이 포함되므로 ‘terrain’이라는 이름만 보고 평지로 간주하거나 창문 무늬를 일괄 적용하면 안 된다.

수정 전 약 384 MiB 타일 캐시가 가득 찬 상태에서 건물/기반 시설의 빈 JSON 조상과 형제 분기를 모두 기다렸다. 시작 후 30초 더 기다린 기록에서도 실제 건물 메시 0개, 기반 시설 메시 0개였으며 요청 거절이 남았다. 단순한 텍스처 실패가 아니라 계층 표시를 막는 로딩 의존성이었다. `baseline-settled.json`과 `before.json`에 원본 계측을 보관했다.

근거리 사진 재질은 이방성 필터링 1배였다. 원본에 존재하는 늘어진 벽 사진과 거친 바닥/수목 형상도 화면에서 확인했다. 이는 필터링만으로 원래 세부를 복원할 수 없는 부분이다.

## 2. 적용한 수정

1. **건물 표시 누락 해결**: 사진 지형의 부모/형제 타일 보존은 유지한다. 빈 조상을 가진 건물·기반 시설은 자신의 콘텐츠가 준비되면 독립적으로 표시한다. 타일 캐시 용량을 무작정 늘리지 않았다.
2. **품질별 상세도 분리**: 사진 지형/건물/기반 시설의 화면 오차를 low 20/20/24px, balanced 10/12/16px, high 6/8/10px로 구성했다. 실제 카메라의 전체 가시 거리는 유지한다.
3. **캐시 압력 안정화**: 요청을 거절하는 계층에만 상세도 완화를 적용한다. 캐시 사용률이 80% 미만으로 내려오기 전에는 즉시 다시 선명하게 만들지 않아 반복적인 상세도 왕복을 억제한다. 한 타일의 추가 완료로 예산을 소폭 넘을 수 있으므로 이 예산은 전체 메모리의 엄격한 상한이 아니다.
4. **텍스처 필터링**: GPU 한도 내에서 balanced/high 최대 8배, low 최대 2배를 적용한다. 원본 색 공간·픽셀·밉 체인·좌표는 유지한다.
5. **대체 재질만 외벽 보강**: 건물 계층의 실제 무채색 1×1 텍스처만 추가로 인식한다. 사진·정점 색상·투명 재질은 덮어쓰지 않는다. 같은 재질을 공유하는 메시도 필요한 법선을 각각 생성한다.
6. **빛과 금속 표현**: 홍콩 전용 하늘 환경 반사를 추가해 그림자 속 금속 캐릭터/차량이 검게 뭉개지는 문제를 줄인다. 태양·반구광을 조정하고 플레이어를 따라가는 제한된 그림자 범위를 적용한다. 사진 지형은 이미 구워진 조명을 가지고 있으므로 도시 전체 사진 메시를 그림자 패스에 중복 투입하지 않는다.
7. **분석 도구**: 검증 모드에 계층별 표시/요청/재질/그림자/캐시 계측과 주변 120m 구역의 49개 수직 지형 표본을 추가했다. 게임의 이동·전투·온라인 판정은 변경하지 않았다.

관련 구현: `src/HongKongRendering.js`, `src/UrbanGroundCity.js`, `src/CityFacades.js`, `src/main.js`. 검증 도구는 `src/QualityDirector.js`와 `scripts/review-hong-kong-rendering.mjs`이다.

## 3. 실제 결과

| 항목 | 수정 전 관찰 | 최종 관찰 |
|---|---:|---:|
| 실제 건물 메시 | 0 | 25 |
| 기반 시설 메시 | 0 | 1 |
| 근거리 표본 텍스처 이방성 | 1배 | 8배 |
| 무채색 대체 외벽 보강 | 0 | 3개 재질 적용 |
| 시작 좌표 | (0, 20.513, 0) | (0, 20.513, 0) |
| 페이지/셰이더 오류 | 0 | 0 |

메시 수는 동일 시작 구역의 관찰 시점 값이며 지도 전체 건물 수가 아니다. 카메라 방향에 따라 표시 수가 달라진다. 전후 시작 이미지는 같은 크기/시작 위치/방향이며, 실시간 로딩 상태와 애니메이션 프레임까지 동일한 것은 아니다.

최종 실제 플레이:
- 키보드 걷기·점프·카메라 복귀: 약 4.3초 동안 13.24m 이동, 좌표 유한성 확인.
- 실제 홍콩 충돌 표면에 마우스로 와이어 연결: `SWINGING`, 와이어 1개 확인.
- B 호출→운전석 옆 배치(명시적 QA fixture)→B 탑승→W 주행→B 하차 확인. 실제 차량 이동 약 3.61m 후 장애물에 정지했다. 장거리 운전 검증이 아니다.
- 서로 다른 두 카메라 방향으로 타일 교체 및 건물 표시 확인.
- 주변 49개 지형 표본 모두 실제 충돌 표면을 반환했다. 옥상과 지면을 함께 측정한 결과이므로 ‘전 구역 보행 가능’이라는 의미는 아니다.

최종 첫 진입은 17.45초였다. 수정 전 22.75초, 중간 실행 82.94초 등 외부 타일 공급과 실행 조건에 따라 큰 차이가 있었으므로 로딩 속도 개선율을 주장하지 않는다. 짧은 이동 평균 약 57.7FPS, 1% low 약 23.1FPS로 순간 지연은 남는다. 고정 60FPS나 장시간 안정성을 보장하지 않는다.

## 4. 검증 및 제외한 변경

- `npm run test:hong-kong:rendering`: 품질/캐시/그림자/대체 재질 검사, 실제 RGB KTX2 보존, 홍콩 스트리밍 충돌 어댑터.
- `node scripts/check-hong-kong-material-webgl.mjs`: 실제 WebGL에서 대체 외벽 무늬, 뒤늦게 대입한 사진의 보존, 하늘 반사에 의한 금속 가독성 확인. 셰이더 오류 0.
- 홍콩 벽 오르기·LOD 충돌 유지·추락 복구, 차량 경사, 카메라/와이어, 로딩 성능 회귀 검사.
- `check-qa.mjs`의 과거 고정 800MiB 기대값을 현재 품질별 예산 검증으로 갱신했다. 서로 다른 도시 인스턴스의 예산 독립성도 확인했다. 28개 QA 경우 통과.
- 일반 이동·컨트롤러·로컬 도시 검사와 프로덕션 빌드 결과는 같은 폴더의 로그에 보관한다.
- 배포용 `dist`를 별도 preview 서버로 실행했다. 개발용 QA API가 없는 상태에서 홍콩 진입, 일반 W/Space 입력, 기초 이동 목표 0→5m 진행, 페이지/셰이더 오류 0을 확인했다(`production-browser.json/png`). 소스 지문과 실제 빌드 지문도 일치한다(`build-identity.json`). 실제 서비스에 배포한 것은 아니다.

거리 기반 추가 오차 완화 실험은 **제외**했다. 광역 타일의 큰 경계 부피 때문에 근거리 지형도 거칠어져 시작 높이가 35.161m로 변하고 차량 탑승 검사가 실패했다. 최종본의 거리 완화 값은 0이며, 시작 높이 20.513m와 실제 탑승을 재검증했다. 실패 증거는 `rejected-distance-falloff.json/png`에 남겼다.

## 5. 아직 해결되지 않은 범위와 다음 제작 순서

이번 수정은 렌더링 계층 누락, 재질 처리, 빛과 캐시 동작을 개선했다. **원본의 뭉개진 벽 사진, 일부 거친 지형·수목 형상, 근거리 세부 부족은 여전히 남는다.** 사진의 해상도를 조작해 실제 디테일이 복원된 것처럼 보고하지 않는다.

후속 제작은 다음 순서가 적합하다.
1. 시작 구역의 늘어진 외벽과 사진 지형 접합부를 실제 좌표에 맞는 정밀 모델/재질로 교체한다. 원본과 보강 모델의 표면 중복 및 충돌 정렬을 함께 처리한다.
2. 주요 거리·옥상의 작은 대표 코스를 대상으로 보도·입구·설비·간판을 수작업 배치한다. 임의 장식으로 실제 경로나 차량 출구를 막지 않도록 검증한다.
3. 거칠게 재구성된 수목/조경 구역은 원본 형상을 선택적으로 마스킹하고 식생 모델로 대체한다. 의미 정보 없이 모든 녹색 표면을 나무로 판정하지 않는다.
4. 대표 구역의 완성도를 확인한 뒤 주변으로 확장한다. 실제 휴대폰, 장시간 메모리/발열, 느린 통신, 전 지도 좌표 검증은 별도 필요하다.

실제 모델 교체와 지역별 미술 제작은 이 변경에 포함되지 않았다. 따라서 앞서 제시한 65~75점 목표가 달성됐다고 판정하지 않는다.
