# 홍콩 시작 구역 정밀 모델 교체

2026-10-29. 실제 스트리밍 홍콩 지형을 조사하고 시작 구역의 외벽 6면과 수목 7곳을 재제작했다. 홍콩 전체나 모든 건물을 교체한 작업은 아니다.

## 적용 범위와 그래픽 변화

- 실제 타일에서 수직 외벽의 삼각형·방향·치수를 추출했다. 선정한 6면의 평면 오차는 10cm 미만이며 기존 외곽과 높이를 따른다.
- 유리 패널 1,967개와 알루미늄 창틀 부품 7,868개를 입체화했다. 실제 폴리곤 밖이나 개구부를 가로지르는 창문은 생성하지 않는다. 유리에는 거칠기·클리어코트와 시작 광장의 128px 지역 환경 반사를 적용했다.
- 사진으로 뭉개진 수관 7곳을 잎·줄기·가지·하부 관목 모델로 교체했다. 줄기와 35개 주요 가지는 별도 형상으로 제작하고 기존 수목 에셋의 잎·수피 재질을 활용했다. 수관·관목은 총 140개 잎 군집을 인스턴싱한다.
- 수목 주변에는 보이는 조경 토양을 추가했다. 수목의 원래 보수적인 충돌 형상은 유지하며 새 토양을 이동용 충돌 바닥으로 사용하지 않는다.
- 교체 모델 뒤의 사진 표면은 지정 외벽의 폴리곤 마스크와 검토한 수관 범위 안에서만 제거한다. 수목 마스크는 사진 지형 계층에만 적용하며 평평한 바닥과 별도 건물·기반 시설 계층을 보존한다. 수목 에셋이 준비되기 전에는 원본 수관을 유지한다.
- 같은 폴더에서 진행 중이던 시작 테라스 표면 개선 코드를 보존해 통합 상태에서 검사했다.

이 외벽은 실제 치수와 외곽을 바탕으로 만든 새 외장이다. 흐릿한 사진에서 실제 건물의 모든 창문·내부 구조를 복원했다는 뜻은 아니다. 지역 반사는 로딩 시 한 번 캡처하며 움직이는 차와 시민을 매 프레임 반영하지 않는다.

## 기존 기능 보존

교체 모델은 원본 스트리밍 지형과 분리된 렌더링 그룹이다. 원본의 위치·삼각형·온라인 판정을 교체하지 않는다. 모델을 켜고 끄는 동일한 실행 시점에서 실제 충돌 지지점 49개의 결과가 정확히 같음을 확인했다.

실제 Chrome 입력 검증(`play.json`):
1. W 이동·Space 점프·X 카메라 복귀.
2. 실제 스트리밍 표면에 마우스로 와이어를 연결하고 스윙.
3. 새 외벽 위치에서 F+W로 벽 오르기.
4. B 호출·탑승, W 주행, 장애물 정지, B 하차. 최종 주행 거리는 약 1.40m다. 장거리 주행 검증은 아니다.
5. low/high/balanced 그래픽 전환.
6. 수목은 실제 장면을 별도 관찰 카메라로 근접 검사했다. 이를 수목 아래에서 걸어 다닌 결과로 보고하지 않는다.

차량 검사는 실제 원본 지형의 높이·경사·공간을 기존 `findParking` 규칙으로 확인한 위치에 QA 플레이어를 배치했다. LOD 변경으로 시작 테라스의 높이와 주차 가능 공간이 달라질 수 있어, 저장해 둔 옛 높이나 가짜 평면을 사용하지 않는다.

최종 짧은 이동 기록은 12.71m, 평균 약 58.2FPS, 1% low 약 22.7FPS다. 순간 지연은 남아 있으며 이 수치가 지도 전체나 모든 기기의 성능을 보장하지 않는다. 최종 플레이에서 페이지·셰이더 오류 및 별도 네트워크 오류 기록은 0개였다.

## 함께 수정한 타일 복구 오류

실제 검사 중 지도 공급자의 HTTP 500 뒤에 `Cannot read properties of undefined (reading 'loadingState')` 예외를 발견했다. 로더의 재시도 메서드가 아직 초기화하지 않은 형제 JSON 노드의 상태까지 읽는 것이 원인이었다.

`TileRecovery.js`는 이미 초기화된 실패 노드만 재시도 상태로 되돌린다. 전체 홍콩 계층을 강제로 파싱하지 않는다. 라이브러리 원본 파일은 수정하지 않았다.

- 실제 `TilesRenderer`의 부분 초기화 트리로 기존 예외를 재현하고 새 복구 경로를 검증했다.
- 브라우저에서 타일 요청 하나에 의도적으로 500을 응답시켰다. 재시도 후 실제 지형 표시, 실패 상태 해소, 미처리 예외 0을 확인했다(`recovery-browser.json`). 의도적으로 주입한 HTTP 오류의 콘솔 기록은 정상적으로 남긴다.

## 에셋·GPU 자원 검증

기존 `SoldierThirdPersonThreeJS/public/models/environment/tree.glb`를 `public/models/environment/hong-kong-pine.glb`로 복사했다. 두 파일의 해시 동일성을 검사했다. 새로운 외부 에셋을 내려받은 작업은 아니다. 원본에 구체적인 이용 허락 메타데이터가 없어 추가 라이선스를 추정하거나 부여하지 않았다.

실제 WebGL에서 수목 조합을 렌더링하고, 수목 요청이 실패할 때 원본 수관을 가리지 않는 것을 확인했다. 소유한 지오메트리·재질·텍스처·인스턴스 버퍼의 해제를 검사했다. 지역 반사는 초기화 후 다시 생성할 수 있고 그래픽 컨텍스트 복구 경로에 연결했다. 전체 장치의 컨텍스트 복구 보증은 아니다.

## 실행한 검사

- `npm run test:hong-kong:district`: 폴리곤/개구부/창문 배치, 원본 지오메트리 보존, 재시도 오류 재현·복구.
- `scripts/check-hong-kong-district-webgl.mjs`: 실제 수목 렌더링, 에셋 실패 시 마스크 보존, 반사 재생성, 자원 해제.
- `scripts/play-hong-kong-district.mjs`: 실제 홍콩 입력과 품질 전환, 지지점 동일성, 같은 프레임 전후 이미지.
- 기존 QA 28개 시나리오, 홍콩 스트리밍·벽·추락 복구, 차량 경사, 카메라/와이어, 미니맵, 시작 테라스, 기존 렌더링 회귀 검사.
- 커밋에 포함되는 파일만 별도 추출해 관련 검사와 프로덕션 빌드를 다시 통과했다. 결과와 빌드 지문은 `COMMIT_VALIDATION.json`에 기록한다. 다른 작업 폴더 변경은 커밋에서 제외했다.

배포용 로컬 실행에서는 개발 QA API가 없는 상태에서 수목 파일 HTTP 200, 일반 W/Space 입력에 따른 기초 이동 목표 0→5m 진행을 확인했다. `WEBGL_lose_context`로 그래픽 연결을 중단·복구한 뒤 일반 재개 버튼으로 플레이와 화면 표시를 확인했다. 페이지·셰이더 오류는 0이었다(`production.json`, `production-restored.png`).

이 배포용 검사에는 원격 WebSocket의 403 응답도 별도로 기록돼 있다. 따라서 위 PASS는 그래픽·솔로 플레이·복구 범위이며 온라인 실서버 접속 성공을 뜻하지 않는다. 온라인 서버나 접속 설정은 이번 변경에서 수정하지 않았다.

## 전후 비교와 남은 범위

`start-before.png`/`start-after.png`, `trees-before.png`/`trees-after.png`는 같은 장면·카메라·타일 상태에서 모델의 표시만 바꿔 연속 렌더링한 이미지다. 거리별 로딩 상태가 다른 별도 실행을 전후 비교로 섞지 않았다. 수목 이미지는 별도 관찰 카메라의 실제 장면 렌더링이다.

교체 범위 밖의 사진 외벽·지면·수목은 원본 상태가 남는다. 선택 영역 안에서도 지면의 작은 요철과 일부 조경 가장자리는 원본을 유지한다. 잎 하나하나에 맞춘 충돌이나 실제 건물 내부, 홍콩 전체 정밀 모델 제작, 실제 휴대폰 발열·장시간 검증은 포함하지 않았다.
