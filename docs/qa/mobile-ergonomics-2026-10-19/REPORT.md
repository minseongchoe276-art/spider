# 모바일 조작 개선 — 2026-10-19

조이스틱을 화면 하단 끝에서 엄지 높이로 올리고, 오른쪽 격자 버튼을 큰 주 동작 버튼과 주변 원형 동작 버튼으로 바꿨다. 가로에서는 넓은 원형 배치, 세로에서는 캐릭터를 가리지 않는 좁은 두 줄의 엇갈린 배치를 사용한다.

## 적용

- 왼쪽 이동 영역에서 처음 손댄 위치를 중심으로 움직이는 플로팅 스틱. 화면 가장자리에 손대도 처음에는 이동하지 않으며, 끝까지 밀면 질주한다. 손을 떼면 기본 높이로 돌아온다.
- 오른쪽 큰 버튼은 왼손 와이어/잽이며 위에는 오른손 와이어/스트레이트를 배치했다. 점프·집·벽 이동·회피·묘기를 추가 메뉴 없이 바로 누를 수 있다.
- 왼쪽 모드 버튼으로 전투를 켜면 벽 이동 자리에 방어, 묘기 자리에 강공격, 집 자리에 훅이 표시된다. 공중에서는 와이어 동작으로 돌아온다. 숨겨지는 방어 버튼의 누름 상태는 해제하되 다른 손의 와이어는 유지한다.
- 와이어뿐 아니라 점프·회피·방어 등 동작 버튼을 누른 채 드래그해도 시점을 움직일 수 있다. 동작 버튼의 6px 미만 손떨림은 조준에 반영하지 않는다.
- 시점·시점 정렬·안내는 ··· 보조 메뉴로 분리했다. 양손 줄과 이동 포인터는 각각 독립적으로 소유하고 해제한다.
- 상태가 같으면 버튼 아이콘·레이블을 매 프레임 다시 쓰지 않는다. 화면 회전·정지·포인터 취소 때 입력을 정리한다.

## 검증

| 화면 | 스틱 중심의 화면 높이 비율 | 최소 버튼 크기 | 겹침 / 잘림 |
|---|---:|---:|---|
| 390×844 세로 | 72.2% | 44px | 없음 |
| 320×568 세로 | 70.8% | 44px | 없음 |
| 844×390 가로 | 64.6% | 44px | 없음 |
| 568×320 가로 | 62.5% | 44px | 없음 |

와이어 화면 4개, 전투 화면 1개 및 펼친 보조 메뉴의 실제 DOM 좌표를 검사했다. 원형 버튼의 외곽 사각형도 서로 겹치지 않았고 모두 화면 안에 있다. 수치는 `layout-results.json`, `extra-layout.json`에 보존했다.

Chrome 실제 화면에서 플로팅 스틱 드래그로 이동하고, 모드 전환 시 빠른 버튼이 교체되는 것을 확인했다. 점프 버튼을 누른 채 조준 드래그한 뒤 실제 고도가 95m에서 102m로 바뀌는 것도 확인했다. 확인한 게임 콘솔 오류는 0개(`browser-errors.json`). 화면 검수는 데스크톱 브라우저의 모바일 크기 및 개발용 `touchReview`로 수행했으며 물리 휴대폰의 촉감/그립 검수와는 구분한다.

- `npm run test:touch`: 플로팅 스틱 획득·질주·화면 가장자리 좌표·복귀·버튼 드래그·손떨림·동시 입력·상황별 숨김 해제 및 입력 생명주기 16개 통과.
- `npm run test:display`: 전체화면·회전·화면 크기 9개 통과.
- `node scripts/check-modal-lifecycle.mjs`: 지도·메뉴·그래픽 손실 전환 통과.
- `node scripts/check-session-flow.mjs`: 플레이 전환 7개 통과.
- `npm run build`: 성공. 기존 대형 메인 청크 경고는 남아 있다.

주요 변경: `src/TouchControls.js`, `src/style.css`, `index.html`, `scripts/check-touch-controls.mjs`. 이번 변경은 모바일 조작에 한정하며 기존 자동 도약 규칙을 유지한다. 로컬 소스와 프로덕션 빌드를 갱신했으며 공개 사이트 배포는 포함하지 않았다.
