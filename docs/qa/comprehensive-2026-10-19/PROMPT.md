# SHADOW PULSE 전체 분야 조사·수정·검증 프롬프트

목표: 이 저장소의 실제 게임에서 재현 가능한 오류, 기능 간 모순, 잘못된 모션과 접지, 입력·세션·네트워크·표시 문제를 조사하고 수정한다. 기존 사용자의 변경을 보존하고, 발견한 결함은 재현 조건과 수정 근거를 남긴다. 경험 연수를 연기하거나 “모든 가능한 상황에서 완벽하다”고 선언하지 않는다. 검사한 사실로 품질을 증명한다.

## 현재 제품 기준

- Three.js + Rapier, 로컬 절차 도시와 홍콩 스트리밍 지형.
- 혼자 플레이, 2~8인 자유 플레이 및 경찰과 도망자.
- 현재 와이어 규칙은 유효한 지상 부착의 자동 도약과 높은 부착점 유지 중 바닥 스침 재도약을 포함한다. 조준 실패는 도약을 만들지 않고, 단순 버튼 해제는 속도를 보존하며, Space는 줄에서 뛰어내린다. 이 규칙을 보존한 상태로 검증한다.
- 기본은 와이어 모드. 지상 전투는 좌클릭 잽, 우클릭 오른손 스트레이트, E 훅, G 강한 스트레이트. 공중에서는 양손 와이어와 집·묘기를 사용한다.
- 세 가지 3인칭 시점, 키보드·마우스·표준 패드·모바일 터치.
- M 전체 지도, H 도움말, Escape 메뉴. 현재 레이스·1인칭·고스트·점수 해제는 제거된 기능이다. 과거 문서를 근거로 복원하지 않는다.
- 온라인 피해와 경기 규칙은 서버 권한을 유지한다. 클라이언트 확인만으로 피해를 허용하지 않는다.

## 조사 범위와 관찰 항목

1. 시작·로딩: 첫 실행, 새로고침, 느린 요청, HTTP 오류, 타임아웃, 원본/컴파일 모션 누락, 외형 누락, 지형 준비 전 진입, WebGL 손실·복구, 시작 버튼 중복 입력.
2. 입력: 누름·유지·해제·빠른 탭·동시 누름·반복 키, 반대 방향, 좌우 modifier, 키 변경·교환, 여러 장치의 같은 동작, 토글 모드, 포커스 상실·숨김·복귀, 대화상자 안 입력.
3. 이동·물리: 걷기·달리기·질주·정지·회전·점프·낙하·착지·구르기, 시간 간격 24/30/60/144 FPS, 프레임 지연, 캡슐 관통, 모서리·천장·좁은 공간·경사·계단·지도 경계·복귀, 비정상 수치 복구.
4. 양손 와이어: 각 손 발사·부착·실패·유지·개별 해제·재부착, 두 줄 길이 제약, 줄 느슨함·장력·가림·동일 메시의 차폐, 점프 해제, 빠른 버튼 교대, 조준점과 대상의 일치, 추가 에너지 발생 여부.
5. 집·벽·난간: 12m 집의 거리·경로·취소·착지, 벽 접촉과 실제 손발 지지, 벽 모서리·정상·막힌 옥상·발판·낮은 옥상, 진입 중 Space, 지형 언로드·LOD 변경.
6. 모션: MotionCatalog의 모든 활성 클립과 내장 대체 클립, 양 외형, 앞·옆·뒤, 시작·타격·회수·루프 끝, 이동 중 공격, 공격 중 점프, 피격·방어·회피·착지 간 전환. 뼈 quaternion 정규화, 관절 제한, 발 미끄러짐·부유·관통, 몸통·손목·발목 연속성과 스킨 늘어짐을 측정한다.
7. 접지: 실제 렌더링된 발바닥 정점과 물리 지형을 함께 검사한다. 경사로 출구·계단에서 충돌 회피 보정으로 발이 올라가면 더 이상 성립하지 않는 이전 접지를 해제한다. 접지 표식만 보고 통과시키지 않는다.
8. 묘기: 모든 방향·종류, 높이 부족·줄 연결·벽·난간·착지·공격과의 상호 배제, 중단·완료·재사용.
9. 전투: 기력·체력·회복·무적·쿨다운·버퍼, 거리·방향·높이·벽 판정, 타격 시점과 화면 동작의 일치, 한 공격의 중복 피해, 방패·가드·회피·슬램·패배·재시작. 투사체는 선분에서 플레이어와 벽 중 먼저 만난 표면을 적용한다.
10. 카메라: 각 모드·방향, 정렬·줌·벽 충돌·천장·좁은 통로, 이동/스윙/벽/난간 전환, 감도·반전·흔들림 감소·FOV, 패드와 터치 조준.
11. UI·접근성: 메뉴·지도·도움말·전체화면의 중복 열기/닫기·포커스·Escape, 게임 정지/재개, 키 변경 안내, 반응형 잘림, 터치 다중 포인터, 전체화면 거부·미지원·WebKit 대체 경로, 문서와 제품 조작의 일치.
12. 저장: 없음·정상·손상 JSON·잘못된 필드·비정상 좌표·용량 부족·접근 차단, 구버전 마이그레이션, 지도별 안전 위치·머리 공간·바닥 재검사, 위치 복귀 시 속도·공격·이동 거리 정리.
13. 온라인 클라이언트: 지연·끊김·재연결·방 가득 참·중복 입장·지도 불일치·늦은 응답·이전 소켓·혼자 플레이 전환, 상대 보간·클립 완료·타격 확인·관전·구조·퇴장. 중복 손 연결, 길이 0의 법선, 과도한 좌표·속도·난간 높이를 거른다.
14. 서버·규칙: 2~8인 준비·시작·경찰 배정·8초 보호·쿨다운·권한·지형 차폐·피해·목표·시간 종료·구조·재경기·퇴장·재접속·서버 재시작, 클라이언트와 서버 도시 충돌체 일치, 비정상 메시지·요청 크기·Origin·인증·RLS·공개 비밀키 노출.
15. 그래픽·효과·음향·성능: 실제 브라우저 렌더링, 양 외형과 모든 모션의 스킨 정점, 와이어·착지·타격 효과, 효과 줄이기·음량·음소거·오디오 장치 실패, 반복 생성/제거 자원 정리, 스트리밍/충돌 예산·FPS·P95·품질 상한·비활성 시간 제외.
16. 제작·검증 신뢰성: 모션 원본과 캐시 해시, 누락 에셋, 프로덕션 빌드, HTTP·프록시·독립 방 서버, 실패 후에도 나머지 검사를 실행하는 통합 결과, 실행 중 소스 변경 감지, 오래된 운영 증거의 재사용 금지.

## 검증과 완료 조건

- 먼저 git 상태와 현재 구현을 확인하고 외부 작업을 덮어쓰지 않는다. 실제 실패를 보존한 뒤 원인을 수정한다.
- `npm run test:comprehensive`와 `npm run build`를 실행한다. 검사별 로그·종료 코드·경과 시간·소스/에셋 SHA-256을 저장한다.
- 실패가 실제 게임 결함인지, 낡은 테스트 준비 조건인지 구분한다. 허용 오차를 늘리거나 테스트를 빼서 통과시키지 않는다. 테스트 전제가 잘못되었다면 제품 규칙과 맞는 실패/성공 두 경로를 검사한다.
- 실제 브라우저에서 로컬 도시 진입, 이동·점프·모드 전환, 지도·도움말·메뉴의 열기/닫기, 전투 연습을 관찰한다. 화면과 콘솔 오류를 확인한다. 자동 포즈 수치만으로 모션의 예술적 자연스러움을 보장하지 않는다.
- 수정 뒤 관련 회귀 검사를 재실행한다. 최종 전체 검사 도중 소스가 바뀌면 결과를 최종본의 통과 증거로 사용하지 않는다.
- 운영 DB·실제 인터넷 2~8인·실제 모바일/Safari/패드·장시간·다양한 GPU 검증은 로컬 통과와 별도로 표시한다. 운영 인증/배포가 없는 검사를 완료했다고 쓰지 않는다.
- 결과에는 발견 문제, 변경 파일, 재현 조건, 검사 명령과 통과/실패 수, 시각 확인 범위, 남은 미검증 범위를 기록한다. 발견한 해결 가능한 실패가 남아 있으면 계속 수정한다. 환경상 검증하지 못한 항목은 차단 사유와 다음 필요한 검사로 남긴다.
