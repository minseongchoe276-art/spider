# 게임 종합 감사 및 수정 기록 — 2026-10-11

최신 추가 수정과 검증 판정은 [두 번째 검토 보고서](review-2/REPORT.md)를 참조한다. 이 문서는 최초 감사 시점의 기록이다.

출시 판단: **상용 출시 보류 / 데스크톱 이동·스윙 프로토타입 조건부 사용 가능**.

확인한 기능 오류를 수정하고 실제 프로덕션 빌드에서 로컬 도시와 홍콩 지도 시작, 이동, 점프, 메뉴, 레이스 진입을 검증했다. 최종 `npm test`는 기존 모션·컨트롤러·게임플레이 검사와 새 QA 회귀 시나리오 34개를 통과했다. 빌드 성공, 의존성 감사 결과 취약점 0건이다. 이것은 전체 지도, 모든 기기, 모든 플레이 상황의 통과를 뜻하지 않는다.

남은 핵심 조건은 홍콩 외부 지도 일부 텍스처 오류, 실제 플레이로 전체 레이스 완주 및 전체 구역 순회, 장시간 안정성, 지원 기기 기준 확정, 캐릭터·명칭·모션·지도·폰트의 공개 배포 권한 자료 확인이다. 확인하지 못한 사항을 통과로 쓰지 않았다. 전문가 관점의 검토 기준을 적용했으며 실제 44년 경력을 주장하지 않는다.

## 범위와 환경

- 사용자 최신 요청인 “찾고 수정해”를 우선하여 첨부 프롬프트의 감사 전용 제한과 달리 동작 수정까지 수행했다.
- 대상은 루트 `spiderman-web-swing`이다. 하위 `spiderman-game/`는 별도 Vite 초기 프로젝트로, 이 게임의 실행 진입점이 아니며 변경하지 않았다.
- Git 저장소가 없어 수정 전 소스를 `docs/qa/source-before-fixes.tar.gz`로 보존했다. 원본 GLB·FBX는 삭제하거나 덮어쓰지 않았다.
- 검증 중 다른 작업의 동일 파일 변경이 관찰됐다. 해당 입력·웹 당기기 구현을 보존했고 함께 검증했다. 최종 파일 해시는 `evidence/source-manifest.json`에 기록했다.
- 환경: macOS 27.0 (26A428), MacBookPro17,1, 8 CPU, 16 GiB RAM, Node 22.19.0, npm 10.9.3, Codex 인앱 브라우저. 별도 Safari/Firefox/Windows/iOS/Android 실기기 검증은 하지 않았다.
- 엔진/의존성: Three.js 0.170 계열, Rapier 0.21 계열, 3d-tiles-renderer 0.5.3, fflate, Vite 7.3.7. 실제 잠금 버전은 package-lock.json에 고정돼 있다.
- 실제 QA 서버: `PORT=5175 npm start`, `http://127.0.0.1:5175/`, 로컬 도시는 `?city=procedural`. 개발 HMR이 입력 상태를 초기화할 수 있어 최종 수동 검증은 dist 서버에서 했다.

## 구현된 게임의 성격

키보드·마우스로 도시를 탐색하는 3D 이동 프로토타입이다. 걷기/달리기/질주, 점프, 공중 제어, 벽 달리기/벽 점프/옥상 진입, 웹 부착/연속 발사/해제, 앵커 당기기 후 스윙, 공중 웹 집, 공중 묘기, 네 가지 카메라, 두 도시 방식, 8링 타임트라이얼이 있다. 사망/체력/전투/적 AI/보스/스토리 미션/로그인/결제/멀티플레이는 구현돼 있지 않다. 추락·경계 이탈은 안전한 시작점으로 복구한다. 진행 위치 저장은 없고 설정과 코스별 최고 기록만 브라우저에 저장한다.

## 아직 남은 문제와 판정 제한

**R01 P2 — 홍콩 지도 일부 텍스처 실패 (실패).** 실제 기본 지도 초기 로딩/이동에서 `THREE.GLTFLoader: Couldn't load texture blob:...`가 여러 번 기록됐다. 지도는 시작 가능하고 충돌 지형도 존재하지만 일부 시각 표면이 완전하지 않다. 콘솔은 `evidence/hong-kong-console.json`에 보존했다. KTX2 MIME 경로는 처리했으나 모든 오류 이미지의 원본 타일/인코딩을 특정하지 못했다. 원인은 아직 확정하지 않았다. 라이브러리는 3D Tiles 1.1 이상 지원 제한 경고도 낸다. 이 경고가 해당 텍스처 오류의 원인이라는 증거는 없다. 다음 검증은 실패 이미지의 원본 tile URL/MIME/바이트를 연결하고 실제 브라우저 디코더와 호환성을 확인하는 것이다. 외부 원본 데이터 손상과 클라이언트 디코딩 오류를 구분해야 한다.

**R02 P1 — 홍콩 코스 가용성 및 실제 8링 완주 (일부 실패/미검증).** 로컬 코스 진입은 최종 빌드에서 확인했고 판정/완료/저장 로직은 자동 시험했다. 홍콩은 앞선 실행에서 진입했으나 최종 빌드 재실행에서는 지형/clearance 부족으로 시작이 거절됐다. 전체 코스 영역을 미리 로드하는 경로가 없어 시작 시점에 필요한 지형을 보장하지 못하는 실패 범위가 남는다. 사람의 플레이로 8링 전부를 완주하지 않았다. 각 링의 반경 주변 6방향 clearance 검사는 전체 원판·접근 경로의 기하학적 도달 가능성을 보장하지 않는다. 첫 홍콩 링은 한 시험에서 +110m/거리117m였다. 웹으로 상승 가능한지, 난도와 다음 목표 안내가 적절한지는 플레이 완주가 필요하다. 출시 전에 두 지도 완주, 취소/재시작, 낙하 복구, 고속 통과를 조합해야 한다.

**R03 P2 — 배포 크기/초기 JS 비용 (확인).** 최종 JS 메인 번들은 약5.25MB, gzip 약1.90MB이며 Vite의 큰 청크 경고가 남았다. 모션 JSON은8.60MiB(20클립), 기존 고유 FBX는124.84MiB(18파일)로 런타임 모션 데이터 경로가 약93.1% 작아졌다. 원본 FBX는 보존돼 dist에도 복사되므로 전체 배포 용량이93.1% 감소했다고 말할 수 없다. 공개 배포 시 원본 제작 자료 분리와 Rapier/지도 코드 지연 로드를 검토하고 초기 저사양 로딩을 측정해야 한다.

**R04 P1 검증 조건 — 장시간/기기 호환성 (미검증).** CPU/GPU 사용량, 전체 브라우저 메모리,1% low, 수시간 실행/반복 재시작 GPU 해제, 고속 홍콩 전 구역 순회, 실기기 입력 지연을 측정하지 않았다. 캐시384MiB는 라이브러리 타일 캐시 목표이며 브라우저 전체 메모리 제한이 아니다. 큰 단일 리소스의 추가로 잠시 넘을 수 있다. Rapier collider 생성은 동기식이라 큰 생성 작업의 정체 가능성이 남는다.

**R05 출시 자료 — 권한/지원 범위 (미검증).** 로컬 캐릭터 GLB, Mixamo 경로가 남은 FBX, Spider-Man 이름·캐릭터, 홍콩 Lands Department 지도, Google Fonts의 자료별 이용 조건/권한 확인 기록이 충분하지 않았다. 법적 허용 여부를 단정하지 않았다. 목표 플랫폼/성능 기준/사용자군도 명문화가 필요하다. 터치/게임패드/키 재지정/감도 슬라이더/화면 판독기 플레이 지원은 현재 없다.

**R06 구조 개선 (코드 검토).** main에 입력·UI·렌더·상태가 함께 있어 상태 조합 수정 시 결합도가 높다. 앱 전체의 requestAnimationFrame/DOM listener/타이머를 정리하는 통합 destroy 경로는 없다. 단일 페이지 단일 인스턴스 실행에서는 즉시 중복이 재현되지 않았으며 이를 확정 런타임 결함으로 분류하지 않았다. SPA에 포함하거나 hot remount를 지원할 때 lifecycle 분리를 검증해야 한다. `WebSwinger.js`는 실제 진입점에서 사용되지 않는 이전 구현이다. 기존 작업 보존을 위해 삭제하지 않았다.

## 성능 관측

- 인앱 브라우저 데스크톱 창, 낮음 품질(DPR 상한1/그림자 꺼짐), 효과 줄이기 켜짐. 최종 저장 화면은1280×720이다. 좁은 약543px 폭 창의 메뉴/도움말도 확인했다. 이는 터치 지원 시험이 아니다.
- 정지/짧은 이동 구간 HUD 표본은 두 지도에서 주로60FPS/16.7ms였다. 시작/로딩 직후에는54~55FPS/18ms 수준 표본도 관찰했다. 지도 정밀도가 갱신되는 레이스 화면에서는36FPS/27.6ms 표본도 확인했다. 단기 화면 표본이며 구간 평균/최저/1% low로 보고하지 않는다.
- 정상 로드 후 홍콩 debug 표본: roots3, meshes84, collisionMeshes72, pending0, 바닥약19.52m, tile cache 약302.6MB. 표본은 `hong-kong-stream-stats.json`에 별도 보존했으며 이동 후 수치와 다를 수 있다.
- 로딩 시간의 정식 분포, GPU 메모리, CPU/GPU %, 메모리 증가 곡선은 측정하지 않았다. 목표 기기/60FPS 기준은 제안할 수 있으나 현재 제품 요구사항으로 확정되지 않았다.

## 출시 전 재검증 순서

1. 실패 텍스처의 원본을 특정하고 오류 없는 지도 표면을 확인한다. 홍콩 레이스 전체 영역의 미리 로딩/도달 가능한 링 배치도 구현·검증한다. 네트워크 단절/20초 지연/복구·캐시 포화를 함께 시험한다.
2. 두 지도에서8링 실제 완주, 코스 재생성/최고기록 분리, 링 접근 난도, 웹 부착/당기기/해제/벽/낙하 조합을 확인한다.
3. 대상 브라우저/최저 사양을 정하고 장시간 구역 순회와1% low/메모리/LOD 접합·카메라 관통을 측정한다.
4. 공개 배포 권한·출처를 자료별로 기록한다. 프로덕션 HTTPS/지도 프록시 경로를 배포 환경에서 확인한다.
5. 최종 소스 해시를 고정한 빌드로 npm test/build/audit를 실행하고 회귀 표·스크린샷·측정 로그를 갱신한다.

이 보고서 이후 다른 작업이 파일을 변경하면 현재 검증 결과를 해당 새 버전에 그대로 적용하지 않는다. 실패/미검증 조건이 남아 있어 “완벽” 또는 “버그 없음”으로 판정하지 않는다.
