## 판단 기준과 범위

장기 경력의 게임 디렉터·클라이언트 개발자·전투/이동 설계자·테크니컬 아티스트·QA·운영 담당자가 출시 전 따질 관점을 나눠 검수했다. 실제 44년 경력을 보유했다는 주장이 아니라, 사용자가 요청한 엄격한 평가 관점을 적용한 것이다.

대상은 현재 작업 폴더의 수정·추가 파일을 포함한 소스다. 검수 시작 시 Git에는 이미 다수의 미커밋 변경이 있었다. 기존 변경을 되돌리거나 게임 기능을 수정하지 않았다. 빌드 결과와 검증 자료를 생성했다. 기존 검사 일부는 자신이 정한 과거 QA 폴더에도 결과를 다시 기록한다.

검증은 자동 검사, 실제 브라우저 조작, 독립 결함 재현, 빌드·전송 검사, 공개 서비스의 읽기 전용 상태 확인으로 구성했다. 자동 검사에는 실제 물리·리그·WebSocket·로컬 PostgreSQL을 사용하는 검사와 DOM 대체물·고정 지형·소스 계약을 사용하는 검사가 섞여 있다. 검사 묶음 수를 실제 사용자 수나 완전한 종단간 시나리오 수로 해석하면 안 된다.

## 핵심 평가

**이동·와이어·전투·모션·혼자 탐험·소규모 온라인의 구현 기반은 갖춰져 있다. 다만 전체 지도에서 재현되는 시각적 결함이 있고, 운영 버전 일치·실기기·장시간·인터넷 실전 검증이 남아 있어 상용 출시 품질 전체를 통과했다고 판단할 수 없다.**

기능적 안정성과 재미·완성도는 별도로 평가해야 한다. 아래의 검사 통과는 정해진 조건에서 규칙과 상태가 일관된다는 뜻이다. 반복 플레이의 재미, 타격의 청감, 모든 모션의 자연스러움, 신규 플레이어의 학습 성공률을 입증하지는 않는다.

최종 실행 수치와 소스 동일성은 [자동 검사 결과](full/results.json)와 [소스 해시 비교](full/source-snapshot.json)를 기준으로 한다. 별도의 모바일 이동·5개 지도/언어 검사 로그도 이 폴더에 보존했다.

## 확인된 결함과 우선순위

### F-01 · P2 · 네온 도심 전체 지도에서 건물과 도로 구분이 무너짐

- 재현: 네온 도심 → 혼자 플레이 → M으로 전체 지도 열기.
- 실제 화면: 작은 건물들이 서로 붙은 큰 청록색 영역처럼 보이고, 도로·건물 윤곽을 읽기 어렵다.
- 원인: [WorldMap.js](../../../src/WorldMap.js)의 도로 그리기에서 설정한 `ctx.lineWidth`가 건물 테두리를 그릴 때도 유지된다. 현재 1280×720 화면의 520px 지도에서는 건물 폭 47.6px에 선 두께 41.65px가 적용된다.
- 증거: [실제 화면](world-map-defect.jpg), [독립 재현 수치](map-defect.json), [재현 코드](reproduce-map.mjs).
- 비교: [선셋 항만 영어 지도](harbor-map-en.jpg)에서는 도로의 굵은 선 설정 경로를 거치지 않아 건물 테두리가 구분된다.
- 영향: 충돌·이동을 막는 치명적 오류는 아니지만 길 찾기와 지도의 신뢰도를 떨어뜨린다.
- 수정 기준: 건물·외곽선을 그리기 전에 명시적인 선 두께를 설정하거나 캔버스 상태를 저장·복원해야 한다. 수정 후 네온 도심·항만·다른 지도와 작은 화면의 실제 렌더링을 확인해야 한다.
- 상태: **검수 요청에 따라 원인과 재현 자료를 남겼으며, 게임 코드는 수정하지 않았다.** 재현 스크립트의 성공 종료는 결함이 존재함을 확인했다는 뜻이다.

### R-01 · 출시 검증 공백 · 공개 서비스와 로컬 빌드가 동일한 산출물이 아님

공개 사이트는 HTTP 200, 방 서버는 HTTP 200 및 `status: ready`를 반환했다. 사용자 설정 경기·명명 대상·공격 결과·방어·모션 단계 기능 플래그도 응답에 있다.

그러나 공개 사이트의 진입 파일은 `/assets/index-D2uwNvIE.js`, 이번 로컬 빌드는 `/assets/index-DnCajlUR.js`다. 파일명이 다르다는 것은 동일 산출물임을 확인하지 못했다는 뜻이며, 그 자체로 특정 기능의 배포 누락이나 고장을 확정하지는 않는다. 운영 서버가 응답한 revision도 기록했다. [상태·빌드 비교](public-surface.json).

따라서 이번 로컬 검증 결과를 공개 서비스 전체의 검증 결과로 대체할 수 없다. 최종 배포 산출물과 서버 revision을 고정한 뒤 운영 환경에서 방 생성·참가·시작·종료·재접속을 검증해야 한다. 이번에는 공개 방을 만들거나 운영 데이터를 변경하지 않았다.

### R-02 · 성능 위험 · 다운로드·파싱 비용과 배포 용량

프로덕션 빌드는 성공했으나 500kB 초과 청크 경고가 남는다. 주요 JS 파일은 `StreamedCollision` 약 4.34MB / gzip 1.65MB, 진입 청크 약 1.28MB / gzip 0.36MB다. 이는 파일 크기이며 실제 최초 방문 전체 전송량과 같지는 않다.

정적 자산 44개에 대해 원본 합계 19,722,538바이트, gzip 6,139,817바이트, Brotli 5,847,844바이트가 생성됐다. 실제 HTTP의 압축 해제 후 바이트 일치·HEAD·406·404·숨김 파일 403 검사는 통과했다. [빌드](build.log), [HTTP 검사](http.log).

`dist`는 로컬 디스크에서 약 208MiB다. `public/models`에는 17MiB 안팎의 원본 FBX 여러 개와 GLB가 포함된다. 원본 FBX는 컴파일 모션 실패 시 복구 자산으로 쓰일 수 있으므로 무조건 불필요한 파일로 단정할 수 없다. 배포 용량과 실제 초기 전송량을 분리해 예산을 잡아야 한다. 현재 압축 스크립트의 대상 확장자에는 FBX·GLB가 포함되지 않는다.

### R-03 · 제품 검증 공백 · 장기 재미·난이도·콘텐츠 밀도

기초 안내 6단계와 옥상 탐사·구역 탐방·500m 순찰·물품 회수/배달·이동 기술 훈련을 확인했다. 마지막 결과·완료 횟수·재도전의 구조도 있다. 예전 보고서의 “탐험 목표가 전혀 없다”는 식의 평가를 현재 버전에 적용하면 잘못이다.

반면 임무를 몇 번 반복했을 때 새로운 선택과 숙련 목표가 생기는지, 새 플레이어가 스윙·벽 이동·훈련 명중을 이해하는지, 온라인 역할별 승률이 적정한지는 이번 검수로 입증되지 않았다. 신규 사용자 관찰, 임무별 성공/중단 시간, 역할·지도·인원별 승률 표본이 필요하다. 점수·성장·경쟁 기록의 부재는 현재 설계 선택일 수 있으므로 자동으로 버그로 분류하지 않았다.

### R-04 · 공개 배포 준비 자료 · 에셋별 출처 추적

`public/models/sources/LICENSE-CC0.md`와 VFX 라이선스 파일은 존재한다. 다만 이 두 파일의 존재만으로 외형·원본 모션·텍스처·폰트·지도 데이터·브랜드 이름 전체의 출처와 배포 조건이 일괄 입증되지는 않는다. 에셋별 원본 링크·제작자·라이선스·변형·필수 표시의 대응표를 이번에 완결된 자료로 확인하지 못했다. 이는 위반 판정이 아니라 배포 증빙 범위의 한계다.

## 실제 브라우저에서 관찰한 성능

[내보낸 진단 파일](browser-diagnostics.json)은 1280×720, 기본 품질, 픽셀 비율 1.5, 네온 도심의 약 10초 활성 플레이를 기록한다. 5초 단위 두 표본은 각각 60 FPS이고, 33.3ms 초과 프레임은 0개, 각 표본의 최장 프레임은 30ms와 19ms다. 로딩 표시의 startup은 429ms다.

이는 캐시가 있는 개발 서버의 짧은 표본이며, CPU를 쓰는 자동 검사도 병행하고 있었다. 네트워크 초기 다운로드 시험·기기 최소 사양·모바일 60 FPS·장기 안정성의 보증으로 사용할 수 없다. `renderer` 통계는 내보내기 시점 한 프레임의 값이며 최대 부하가 아니다. 관찰한 해당 브라우저 탐색의 오류/경고 수집 결과는 [기록](browser-errors.json)에 있다.
