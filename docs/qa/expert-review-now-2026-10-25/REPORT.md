# SHADOW PULSE 전 분야 검수 보고서

기준일: 2026-10-25(KST). 대상: 현재 작업 폴더의 미커밋 수정·추가를 포함한 코드와 그 코드로 만든 로컬 빌드.

44년차 게임 디렉터가 출시 전에 따질 수준의 관점을 적용했다. 실제 44년 경력을 보유했다는 의미가 아니다. 검수 범위를 기능 규칙, 실제 화면, 운영 동일성, 실측이 필요한 제품 품질로 나누었다.

## 종합 판정

**핵심 기능은 실행한 검사 범위에서 통과했으며, 현재 출시 품질 전체는 승인 보류다.** 새로 재현한 HUD 겹침, 공개 배포의 버전 동일성 미확인, 실제 기기·신규 사용자·역할별 균형 표본 부재가 남아 있다. 이는 게임 전체가 작동하지 않는다는 의미가 아니다.

| 이번에 다시 실행한 항목 | 결과 |
|---|---|
| 전체 자동 검사 묶음 | **107/107 통과, 실패 0** |
| 검사 전후 소스·모델·모션 해시 | **변경 0개** |
| 별도 모바일 이동·5개 지도/언어 검사 | **2/2 통과** |
| 프로덕션 빌드 | **성공**, 500kB 초과 청크 경고 유지 |
| 로컬 전체 파일 HTTP 동일성 | **104개 확인 항목 통과** |
| 압축·HEAD·406·404·숨김 파일 보호 | **통과** |
| npm 감사 | 알려진 취약점 **0건** |
| 실제 Chrome 2탭 로컬 경기 | 방 생성·초대 참가·준비·시작·역할·HP·시작 보호·상대 위치 확인 |
| 별도 실제 화면 결함 | **HUD 겹침 1건 재현** |
| 공개 배포 동일성 | **미통과**: release.json 404, 서버 fingerprint 미제공 |


자동 검사 묶음 수는 사용자 수·시나리오 총수·게임 완성도 점수가 아니다. 실제 물리·리그·로컬 WebSocket·로컬 DB 검사와 DOM 대체물·소스 계약 검사가 섞여 있다. 이번 브라우저 확인은 짧은 로컬 플레이이며 전체 홍콩 답사, 장시간 GPU 시험, 실기기 시험은 수행하지 않았다.

## 확인된 결함

### F-01 / P2 / 중간 너비 화면의 HUD 겹침

재현: 데스크톱 Chrome, CSS viewport 840×844, 기본 HUD 크기 → 네온 도심 → 혼자 플레이. 하단 미니맵이 양손 와이어 상태의 오른쪽 문구를 가린다. 하단 조작 바도 미니맵의 하단 영역과 겹친다.

측정한 사각형:

| 요소 | left | top | right | bottom | z-index |
|---|---:|---:|---:|---:|---:|
| 양손 상태 | 302.99 | 738.80 | 537.01 | 768 | 7 |
| 미니맵 | 496 | 435.82 | 816 | 818 | 22 |
| 조작 바 | 236 | 789 | 569.48 | 824 | 24 |

양손 상태와 미니맵은 수평 약 41px가 겹치며 미니맵이 위에 그려진다. 조작 바와 미니맵도 수평 약 73px·수직 29px가 겹친다. 단순 취향 문제가 아니라 상태 정보가 실제로 가려지는 배치 문제다. 1280×720 비교 화면에서는 이 두 영역의 겹침이 보이지 않았다. 모든 너비에서 정상이라는 의미는 아니다.

원인 근거: `src/style.css`의 미니맵 320px 우하단 고정 배치, 양손 상태 중앙 고정 배치, `src/player-ui.css`의 하단 위치 규칙이 중간 너비에서 함께 적용된다. 레이아웃 공간을 공동으로 배정하지 않는다.

영향: 와이어 상태 이해와 하단 지도 정보의 가독성 저하. 이동·충돌 자체를 중단시키는 오류는 아니다.

수정 수용 기준: 650px 전후·840px·950px 전후·1280px, HUD 배율별로 필수 문구가 미니맵에 가려지지 않아야 한다. 상태 줄을 지도 위 빈 공간으로 이동하거나 HUD 전용 영역을 배정하고 실제 화면으로 확인한다. 이번 요청은 검수·보고이므로 게임 코드를 수정하지 않았다.

증거: [840px 원본 화면](solo-hud.png), [1280px 비교](desktop-1280.png).

### 이전 전체 지도 결함 / 현재 수정 확인

과거 보고서의 도로 선 두께가 건물 윤곽에 새는 문제는 현재 `WorldMap.js`에서 건물 1px, 경계 1.5px로 재설정한다. 실제 네온 도심 전체 지도에서 얇은 건물 윤곽을 확인했고, `check-release-readiness`는 5개 지도 × 3개 화면 × 반복 그리기를 검사한다. 과거 결함을 현재 미해결 결함으로 재보고하지 않는다. [현재 지도 화면](world-map.png).

## 모션·전투 정량 근거

이번 실행에서 33개 모션의 전체 재생은 99개 FPS 조건·15,309프레임을 검사했다. 클립 전환은 1,089쌍 × 3개 프레임률 = 3,267회·77,319프레임이다. 최종 말단 관절 검사는 272/272 조건·41,564프레임을 통과했다. 전투 품질 24개 조건은 접촉 시점·이동 중 공격·렌더링 관절 한도를 확인했다. 이 수치는 정량 검사 범위이며 움직임의 미학·타격감에 대한 사용자 평가 점수가 아니다.

## 용량 판단

이번 릴리스 목록의 역할별 준비된 압축 크기는 bootstrap 365,688B, 캐릭터 그룹 26,400,656B, 복구용 원본 그룹 29,804,667B다. bootstrap 예산·캐릭터 예산·전체 예산은 통과했다. 로컬 서버에 대해 전체 파일 HTTP 동일성 검사 104개 항목도 통과했다. 캐릭터 그룹 전체가 첫 프레임 전에 내려받아진다는 의미는 아니다. 최초 방문의 요청 순서·캐시·호스트 압축·파싱·GPU 업로드 비용은 별도로 측정해야 한다.

원본 복구 자산을 삭제해서 숫자만 줄이는 접근은 권하지 않는다. 실제 사용 경로와 실패 복구 기능을 유지하면서 초기 로딩과 후속 로딩을 계측해야 한다. Vite의 500kB 초과 청크 경고는 유지된다. 빌드 성공이 저사양 성능 합격을 의미하지 않는다.

## DB 검토 기준

Supabase 스킬과 [공식 RLS 문서](https://supabase.com/docs/guides/database/postgres/row-level-security)를 참고했다. 테이블 권한과 행별 정책을 함께 확인해야 한다는 기준으로 로컬 마이그레이션의 RLS 활성화·직접 테이블 접근 회수·RPC 실행 권한·고정 search_path를 확인했다. 로컬 자동 DB 검사의 통과는 운영 DB의 동일한 권한 상태를 보증하지 않는다. 이번 운영 DB의 새 조회나 변경은 하지 않았다.
