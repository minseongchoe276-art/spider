# 자율 게임 재검수 — 2026-10-30

## 이번에 발견하고 수정한 문제

기존 수정이 많이 남아 있는 작업 폴더를 그대로 유지하고, 현재 실행 코드와 자동 검사 및 Chrome 플레이 시나리오를 재검수했다. 기존 보고서의 개선 내용을 이번 작업의 성과로 중복 계산하지 않는다.

키보드는 컨텍스트 손실과 숨겨진 페이지에서 입력을 거부하지만 마우스 공격·와이어 발사는 같은 조건을 검사하지 않았다. 마우스 시점·휠 줌도 조건이 달랐다. 온라인 도움말은 시뮬레이션을 계속하므로 단순한 일시정지 검사로는 모든 입력을 막을 수 없었다. 네이티브 대화상자가 열렸을 때도 컨트롤러가 합성한 클릭이 게임으로 전달될 여지가 있었다.

`src/main.js`에 `gameplayInputBlocked`를 추가해 키보드 동작, 마우스 공격·와이어, 시점, 줌이 동일한 차단 상태를 사용하도록 했다. 중단 상태, 컨텍스트 손실, 백그라운드, 도움말, 관전, 전체 지도, 열린 대화상자를 검사한다. 키·버튼 해제 처리는 계속 실행해 장치 사이에 눌림 상태가 남지 않게 했다. `src/GamepadInput.js`도 도움말 상태를 명시적으로 검사한다. 온라인 시뮬레이션 진행 여부는 바꾸지 않았다.

## 재현과 확인

- 수정 전 새 회귀 검사에서 컨텍스트 손실 중 좌·우 클릭 공격 2회가 실행되어 실패했다. 수정 후 공격이 실행되지 않는다.
- `scripts/check-input-lifecycle.mjs`: 키보드·패드·터치의 공격과 와이어, 시점·줌 차단 및 정상 복귀를 검사한다. 온라인 도움말에서 스틱 시점도 검사한다. 최종 25개 시나리오 통과: `input-final.log`.
- `scripts/play-self-audit.mjs`: 실제 Chrome에서 이동·일시정지/재개, 임무 목적지와 저장, 이동 타격, 네이티브 대화상자 입력 차단, 390px 화면과 터치 에뮬레이션을 확인한다. 8개 시나리오 통과, 처리되지 않은 오류 0개: `browser.json`.
- `desktop.png`, `narrow.png`, `touch.png`, `moving-combat.png`에 화면을 보존했다. 데스크톱·터치 화면을 직접 확인했다.

브라우저 임무 완료는 목적지까지 위치를 배치한 후 실제 지지·대기·완료·저장 로직을 실행하는 검사다. 전체 경로를 수동으로 이동한 플레이로 간주하지 않는다. 개발 진단 패널은 검수 화면에만 포함된다.

## 검증 기록의 해석

초기 전체 검사 중 새 DOM 조회를 제공하지 않는 최소 테스트 환경에서 실패가 발생했다. 조회를 선택 호출로 바꾸어 최소 환경과 실제 브라우저를 모두 지원했고, 메커니즘 검사 14개와 QA 검사 28개를 재검사했다. 기존 판정 조건은 완화하지 않았다. 처음의 실패는 `suite.json`과 원래 로그에 남기고, 최종 재검사 결과는 `final-suite.json`에 구분한다. 브라우저 최초 실행은 소스 수정에 따른 개발 서버 새로고침으로 중단되었으며, 수정 종료 후 다시 실행한 결과를 `browser.json`에 기록했다.

## 범위와 남은 한계

이 검수는 로컬 코드·회귀 검사·Chrome의 절차 생성 도시 플레이에 대한 검증이다. 실제 휴대기기의 발열·배터리, 운영 온라인 서버의 다인 대전, 홍콩 지도 전체의 수동 시각 검수는 보증하지 않는다. 로컬 도시의 반복적인 외형과 콘텐츠 다양성은 별도의 제작 과제다. 자동 검사 통과를 게임 전체의 무결점으로 해석하지 않는다.

재현: `node scripts/check-input-lifecycle.mjs`, 개발 서버를 실행한 뒤 `QUALITY_URL=http://127.0.0.1:5195 node scripts/play-self-audit.mjs`.
