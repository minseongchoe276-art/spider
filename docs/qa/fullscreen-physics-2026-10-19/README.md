# 전체화면·물리 검증 — 2026-10-19

## 적용 결과

- 로비, PC 게임 HUD, 일시정지 메뉴, 모바일 조작바에 전체화면 전환을 연결했다.
- 표준 Fullscreen API와 WebKit 진입/종료를 지원한다. 브라우저에서 종료해도 버튼 상태를 다시 맞춘다.
- `100dvh`, 화면 안전 영역, ResizeObserver와 visualViewport 변경을 반영해 카메라 종횡비·렌더 크기·속도선·미니맵 크기를 갱신한다.
- 전체화면 전환을 거절하거나 지원하지 않는 브라우저에는 홈 화면 웹앱 실행 안내를 제공한다.
- 웹앱 manifest와 iOS 홈 화면 실행 메타데이터를 추가했다. 오프라인 다운로드 기능은 추가하지 않았다.

## 발견하고 수정한 물리 문제

1. 거미줄을 잡고 바닥에 닿으면 점프 힘 26을 자동으로 넣는 처리를 제거했다.
2. 지면에서 중력을 대각선 줄에 먼저 투영하면서 옆 방향 속도가 누적되던 문제를 수정했다. 정지 상태의 바닥 지지 반력을 반영한다.
3. 거의 반대 방향으로 당기는 양손 줄에서 반복 투영의 느린 수렴으로 길이 제한이 약 0.01583m 초과될 수 있었다. 두 거리 제한 구의 교집합과 두 속도 반공간을 직접 투영하는 방식으로 보완했다.
4. 지상에서 줄을 잡고 있어도 Space/모바일 점프 버튼으로 직접 도약할 수 있다. 공중에서 줄을 놓을 때에는 추가 점프 힘을 넣지 않는다.

## 실행한 검사

모두 통과:

- `npm run test:display`: 전체화면 진입/종료, 브라우저 종료 동기화, WebKit, 거부/미지원 대체 안내, standalone, 연속 클릭, 세로/가로 크기 — 9개 사례.
- `npm run test:physics`: 정량 불변량, 진자, 양손 줄, 기본 이동·충돌, 홍콩 Rapier 지형, 거미줄 연속성, 벽/난간 이동.
- `npm run test:touch`: 터치 스틱·포인터 소유권 검사와 입력 수명주기 15개 사례.
- `node scripts/check-traversal.mjs`: 실제 경사·계단·머리 공간·지지 상실·이동 장애물 등 21개 사례.
- `node scripts/check-mechanics-audit.mjs`: 15개 사례.
- `node scripts/check-player-audit.mjs`: 12개 사례.
- `node scripts/check-camera-motion-web.mjs`.
- `node scripts/check-reticle-only.mjs`.
- `node scripts/check-swing-accessibility.mjs`: 실제 스트리밍 충돌을 포함한 명시적 점프와 부착 검사.

과거의 자동 상향 조준·자동 도약을 요구하던 테스트는 현재 사용자 요청인 조준점 전용 부착·수동 점프 기준으로 바꿨다.

## 화면 확인

- PC: 실제 전체화면 버튼으로 진입/종료. 진입 시 화면과 캔버스 모두 1680×1050, 가로 넘침 없음.
- 모바일 크기: 일반 브라우저 화면을 390×844로 설정해 캔버스 위치 (0,0), 크기 390×844와 터치 버튼 경계를 확인했다. 모바일 조작바의 전체화면 버튼으로 진입/종료 상태가 전환되는 것도 확인했다. 에뮬레이션 호스트 전체화면과 실제 휴대폰의 화면 크기는 동일한 검증이 아니다.
- `desktop-fullscreen.png`, `mobile-viewport.png`에 화면 증빙을 저장했다.
- 실제 iPhone/Android 하드웨어 테스트는 수행하지 않았다. 모바일 크기 검사는 데스크톱 브라우저의 개발용 터치 미리보기다.

## 물리 모델의 범위

현실 전체를 재현하는 완전한 물리 엔진으로 보증할 수는 없다. 현재 게임은 120Hz 고정 스텝, 몸체 충돌 프록시, 늘어나지 않는 줄의 거리 제한을 사용한다.
중력 28m/s², 점프 속도 26m/s, 최대 속도 48m/s, 공중 방향 조절·벽 달리기·웹 집은 슈퍼히어로 조작을 위한 게임 규칙이다.
자유낙하 적분 및 줄 제약에는 위에 기록한 수치 오차·손실이 있고, 실·인체의 탄성/변형이나 바람을 포함하는 연속체 시뮬레이션은 아니다.
