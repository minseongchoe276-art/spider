# 웹 스윙 검사

## 첫 시도는 하늘을 조준했다

`play.json`의 web swing:

- 시작 y 102.6, 상태 FALLING. 직전 점프의 연장이다.
- PageUp 900ms로 피치가 -0.22에서 -1.10까지 올라갔다. 한계는 -1.40이다.
- `playWebShoot` 2, `playWebFailure` 3. `maxWebs` 0. 상태 FALLING → LANDING. 끝 y 0.1.
- 화면 문구: “대상 없음 · 건물을 향해 조준하세요.”
- 스크린샷의 레티클은 하늘이다. 건물은 화면 위에 있고 중앙 픽셀은 빈 하늘이다.

이 거절은 `findBestAnchor`가 중앙 광선에 표면이 없을 때의 정상 동작이다. 제품 버그로 적지 않는다.

양손 시험은 같은 하늘 조준에서 이어서 했고 `maxWebs` 0이다. 양손은 다시 시험하지 않았다. 결과는 UNVERIFIED.

## 조준을 건물에 올린 재시험

`aim-sweep.json`. 요 0, 피치를 고정하고 프레임 두 번 뒤에 `findBestAnchor`를 호출했다.

| 피치 | 첫 히트 | 앵커 |
| --- | --- | --- |
| -0.20 | 없음 | 없음 |
| -0.45 | 없음 | 없음 |
| -0.70 | 없음 | 없음 |
| -0.90 | 12.16m | 있음 |
| -1.05 | 9.80m | 있음 |
| -1.20 | 10.05m | 있음 |

피치 -0.90에서 마우스 왼쪽을 누르고 0.9초 유지.

- SWINGING 44프레임, 웹 1개, 최대 속력 29.12m/s
- 화면 상태 `SWINGING`, 클립 swing, 9.6m/s
- HUD 속도 34km/h. 9.6m/s × 3.6 = 34.6이라 계기판과 맞다.
- 고도 표시 101m. 시작 옥상 95.5m보다 위다.
- `10-settled-swing.png`: 갈색 탱크 표면에 몸이 붙고 흰 줄이 몸 아래에서 표면 쪽으로 간다. 손이 줄의 끝과 일치하는지는 이 크기에서 확인하지 못했다.

같은 프레임의 프로브가 “대상 없음” 문자열을 `webFailureReason`에 남긴 채로 앵커를 반환했다. `findBestAnchor`가 시작할 때 그 문장을 넣고, 성공해도 지우지 않는다. 실패 콜백은 앵커가 없을 때만 쓴다. 플레이어 문구가 성공 중에 뜨지는 않았다. 진단 값이 성공과 실패를 같이 가리키므로 백로그에 남긴다.

## 하지 않은 것

낮은 건물과 높은 건물의 비교, 골목, 넓은 도로, 연속 스윙, 줄 해제 뒤의 관성, 공중 착지, 건물 관통, 양손이 실제로 두 줄인 상태. 도시 전역 스윙이 아니다.

판정: 중앙 광선이 표면을 맞추면 한 줄 스윙은 PASS. 빈 하늘 거절도 PASS. 양손과 도시 다양성은 UNVERIFIED.
