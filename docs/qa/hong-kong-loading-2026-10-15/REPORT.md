# 홍콩 초기 로딩 최적화

## 변경

- 220m 범위부터 기존과 같은 화면 오차/디테일로 지도와 충돌을 준비하고, 시작점 준비 완료 뒤 12초 동안 기존 1,000m 스트리밍 범위로 확장한다.
- 세 지도 계층의 대기열과 충돌 변환 완료, 시작 표면의 600ms 안정성 검사를 유지한다.
- 초기 로딩 중 가려진 게임 화면 렌더링과 3D 미니맵 타일 복제를 생략한다.
- 충돌 변환의 초기 로딩 예산만 프레임당 3ms/6,000 인덱스에서 8ms/24,000으로 늘린다. 플레이 중 예산은 기존과 같다.
- 캐릭터 모션을 한 개씩 요청하던 방식에서 최대 4개 동시 요청으로 전환한다. 실패 시 기존 FBX/대체 모션 동작은 유지한다.
- RGB KTX2 변환 시 픽셀마다 임시 배열 뷰를 생성하던 작업을 제거한다. 색상·알파·밉맵 검증을 통과했다.
- 공개 지도 응답의 브라우저 캐시를 5분으로 설정한다. 기존 응답은 `public, max-age=0, must-revalidate`였다.

## 측정

프로덕션 코드 기반의 분리된 체크아웃, 같은 Chrome 환경 및 Node 프록시를 사용했다. 전/후 첫 측정은 서로 다른 포트(5201/5202)로 브라우저 캐시를 공유하지 않는다. 요청받는 공식 지도 서버의 상태와 시스템 부하는 통제하지 않았으며 단일 표본 비교다.

페이지 탐색 시작부터 게임 준비 완료(`performance.now`, loading-screen의 data-ready-ms)까지:

| 조건 | 준비 완료 |
| --- | ---: |
| 최적화 전 첫 접속 | 22,902ms |
| 최적화 후 첫 접속 | 14,740ms |
| 최적화 후 같은 주소 재접속 | 11,603ms |

첫 표본 기준 35.6% 단축. 최적화 후 캐릭터 준비는 각각 1,393ms와 1,570ms였고 지도 준비가 최종 대기를 결정했다. 측정치는 모든 기기·네트워크에서 보장되는 시간이 아니다.

## 검증

- 프로덕션 빌드 통과.
- 로딩 회귀 검사 4개: 동시 요청 상한/누락 없음, 초기 범위와 전체 범위 복원, 로딩·플레이 충돌 표면 일치, 모든 RGB 채널/알파/밉맵 보존.
- 기존 QA 회귀 36개, 홍콩 스트리밍 8개 및 실제 모션 검사 통과.
- 브라우저: 로딩 완료 후 LIVE, 실제 혼자 플레이 및 W 이동/Space 점프 확인. 오류 로그 없음.
- 같은 로컬 서버에서 로컬 도시도 913ms에 준비 완료되어 정상 플레이 화면 표시를 확인했다.
- 작업 폴더(기존 미커밋 게임 변경 포함)의 로딩 회귀 검사와 빌드도 통과했다.
- 공개 커밋: `b93dd30`. Vercel 배포 완료: https://vercel.com/ms-projects14/spider/4tEjs8MxL23d9BANjwFjHUQjRNtn

공개 검증:
- 공개 지도 루트 HTTP 200, `Cache-Control: public, max-age=300`, `x-vercel-cache: HIT` 확인.
- 공개 홍콩 페이지 준비 완료 16,848ms(캐릭터 3,036ms, 지도 16,848ms), 오류 로그 없음. 공개 방문은 이전 방문의 캐시 상태가 섞일 수 있으므로 위 첫 접속 비교와 분리한다.
- 공개 혼자 플레이 및 W 입력 후 위치가 동쪽 -1m/북쪽 3m에서 동쪽 -3m/북쪽 4m로 바뀜. `public-play.png`에 실행 화면 저장.
- 기존 진행 중인 작업은 유지하고 이번 9개 파일 수정만 공개 main에 배포했다.
