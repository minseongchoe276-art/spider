# 게임 종합 결함 점검 및 수정 — 2026-10-14

현재 소스의 물리·거미줄·벽 이동·착지·전투·묘기·로컬/온라인 모션·키 변경·게임패드·도움말·카메라·그래픽·레이스·저장·미니맵·위치 표시·서버 권한을 점검했다. 확인된 결함을 수정했으며, 모든 가능한 환경에서 결함이 없다는 보증은 아니다.

## 발견한 문제와 수정

| 영역 | 재현된 문제 | 수정 |
|---|---|---|
| 키 변경 | 오른쪽 Shift/Ctrl/Alt가 왼쪽 키의 새 배정을 따르지 않음 | 좌우 수식 키를 같은 실제 배정으로 해석 |
| 동시 키 입력 | W와 ↑ 등을 함께 누른 뒤 하나만 떼면 남은 입력까지 사라짐 | 실제 키별 입력원을 추적 |
| 질주 토글 | Shift 두 개를 누르면 질주가 두 번 토글됨 | 이미 눌린 동작은 다시 토글하지 않음 |
| 마우스·패드 | 게임패드 트리거를 떼면 실제 마우스의 줄까지 풀림 | 입력원별 버튼 상태를 분리하고 마지막 해제만 적용 |
| 카메라 드래그 | 휠 버튼 드래그 중 좌클릭을 떼면 드래그 종료 | 휠 버튼 해제만 드래그 종료 |
| 도움말·음소거 | H/M에 다른 조작을 배정하면 고정 기능에 접근 불가 | 두 키 예약, 설정 화면에서 이유 표시 |
| 게임패드 반응 | 패드 입력이 물리 계산 뒤에 반영됨 | 같은 프레임의 물리 계산 전에 수집 |
| 묘기 | 상승 중 착지 시간을 무한대로 보고 끝낼 수 없는 묘기 시작 | 상승/하강 모두 남은 비행 시간을 계산 |
| 모션 실패 복구 | 모델 로딩 실패 시 묘기 완료가 실행되지 않아 잠김 | 기본 모델도 회전·완료·착지 취소를 처리 |
| 온라인 모션 | 로컬은 점프 자세인데 상대에게는 스윙 자세로 전송 | 동일한 도약 애니메이션 상태를 전송 |
| 방어 | 공격 중 방어 키를 눌러 유지해도 회복 후 방어가 시작되지 않음 | 실제 누름 상태를 매 프레임 반영 |
| 전투 연습 | 치명적인 투사체 뒤 옛 투사체가 복귀한 플레이어에게 남음 | 사망 복귀 시 그 프레임에서 전체 투사체 정리 |
| 도움말 | 혼자 플레이에서 읽는 동안 추락/레이스 진행, Esc는 메뉴를 중첩 | 로컬 물리·타이머 정지, Esc 닫기·닫기 버튼 추가; 온라인 계속 진행 표시 |
| 그래픽 | 자동 해상도 조절을 꺼도 낮아진 해상도가 계속 유지 | 선택한 수동 품질 해상도로 즉시 복원 |
| 온라인 연결 | 종료 뒤 로그인/입장 응답이나 대기 명령이 연결·방을 되살림 | 비동기 단계마다 종료 상태 확인, 대기 명령 취소, 방 코드 폐기 |
| 조작 표시 | 묘기 조합·메뉴·레이스 HUD에는 변경 전 키가 남음 | 실제 설정으로 함께 갱신 |

## 브라우저 확인

로컬 개발 서버 `http://127.0.0.1:5194/?city=procedural`를 Chrome에서 실행했다.

1. 혼자 플레이 진입, 도움말의 일시정지 표시, Esc 닫기, 메뉴 진입을 확인했다.
2. 묘기를 O, 레이스를 L로 변경해 조합 설명·하단 조작·메뉴·두 레이스 HUD가 함께 변경되는 것을 확인했다 (`remapped-controls.jpg`).
3. 기본 키로 복원했다. 검사에 사용한 화면 크기를 원래대로 복구했다.
4. 390×844의 좁은 창에서 도움말이 창 안에 들어오고 가로 넘침과 키 배지 잘림이 없음을 DOM 측정과 화면으로 확인했다 (`guide-narrow.jpg`). 터치 조작 지원 검증은 아니다.
5. 실제 달리기·점프 입력을 실행했다. 옥상 물탱크 아래에서 점프가 천장에 막히고 착지하는 충돌 동작도 확인했다 (`jump-live.jpg`, 파일명은 입력 시나리오).
6. 관찰한 브라우저 error/warn 표본은 빈 배열이었다. 이 관찰은 모든 구간의 무오류를 뜻하지 않는다.

## 범위와 제한

이번 변경은 로컬 소스에 반영했다. 운영 배포와 운영 DB 변경은 수행하지 않았다. 온라인 검증은 로컬 실제 방 서버와 격리 PostgreSQL, 모의 Auth/Realtime 및 전송 재현 검사에 근거한다. 모든 홍콩 공식 지형 구간, 모든 게임패드 실물, 실제 운영 인터넷 지연을 수동 플레이한 것은 아니다.

Supabase 연결 정리는 [공식 removeChannel 문서](https://supabase.com/docs/reference/javascript/removechannel)를 확인하고 기존 API의 생명주기 처리만 수정했다. DB 스키마나 권한은 바꾸지 않았다.
