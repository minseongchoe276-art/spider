# 운영 이동 예산 수정 초안 — 미적용

실제 프로젝트의 마이그레이션 폴더가 아닌 QA 제안 작업공간에 보존했다. 운영 함수는 현재도 기존 20m/패킷 조건을 사용한다. 이 파일을 운영에 적용하거나 검증 완료로 보고하지 않았다.

로컬 WebSocket과 같은 누적 여유(20m, 초당 72m)를 Postgres 행 잠금 안에서 유지한다. 이동이 거부되면 기존 위치 correction을 반환하며 거부 요청으로 예산을 중복 충전하지 않는다. 정상 지연 업데이트는 실제 경과 시간만큼 허용한다. 기존 RPC의 인증·멤버십·지형·피해·역할·목표 처리를 보존한다. 게임 테이블 RLS/직접 접근 금지와 authenticated RPC 권한은 확장하지 않는다.

현재 기기에는 Docker/psql이 없고 독립된 staging 연결도 제공되지 않아 실제 마이그레이션 및 RPC 검증은 BLOCKED다. 운영 DB로 대체 시험을 하지 않았다. 읽기 전용 합성 SQL 수식 시험은 실제 함수 적용·권한·동시 요청 시험을 대체하지 않는다.

적용 전 검증:

1. 새 staging에 현재 저장소의 기존 마이그레이션을 순서대로 적용한다.
2. 제안 파일을 검토하고 staging에 적용해 SQL 컴파일·move_budget 제약을 확인한다.
3. 두 독립 게스트의 방 생성·참가·준비·시작·정상 이동을 확인한다.
4. 60ms 간격의 파이프라인 순간이동 요청을 보내 correction 발생을 확인한다.
5. 정상 48m/s, 500ms 지연, 재접속, 시작·재경기, 구조·낙하 복구를 확인한다.
6. 공격·시작 보호·목표·역할 순환·다른 방 접근·직접 테이블 권한을 재검증한다.
7. RPC 경합·트랜잭션 롤백·시간 역전·실패 후 정상 이동을 확인한다.
8. staging Security/Performance Advisor를 읽고 권한 변경이 없는지 확인한다.

공식 함수 권한 참고: https://supabase.com/docs/guides/database/functions

운영 적용은 이 초안과 별도 검증 결과가 검토된 뒤에 결정해야 한다.
