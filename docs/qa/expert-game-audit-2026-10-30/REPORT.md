# 게임 전체 품질 검토와 적용 — 2026-10-30

## 결론

현재 SHADOW PULSE는 도시 이동, 양손 와이어, 벽 이동, 근접 전투, 차량, 시민, 개인 임무와 온라인 대전을 갖춘 액션 샌드박스다. 기능의 부재보다 **기능 사이의 일관성과 플레이어에게 전달되는 정보의 정확성**을 먼저 개선해야 한다. 장기 개발·출시·운영 관점에서 판단했으며, 코드 검사와 실제 브라우저 관찰을 근거로 우선순위를 정했다.

이번 변경은 현재 작업 폴더에 누적된 기존 변경을 유지하면서 적용했다. 이전 수정 전체를 이번 작업의 성과로 계산하지 않는다.

## 적용 파일

- `src/Character.js`: 첫 이동 타격을 현재 달리기 자세에서 연결. `src/CharacterPose.js`의 크로스 복귀 가슴 방향 보정도 타격 강도에 따라 서서히 해제해 손 튐 제거.
- `src/main.js`, `src/GamepadInput.js`: 입력 중단 상태와 패드 시점 시간 제한.
- `src/CombatPractice.js`: 설정과 언어에 맞는 훈련 조작 설명.
- `src/SoloJourney.js`, `src/MissionRules.js`: 튜토리얼 설정 반영, 목적지 순번, 착지 피드백과 연속 진행률.
- `src/WorldWeather.js`: 효과 감소 설정의 번개 차단, 영어 날씨 표시.
- `src/player-ui.css`: 좁은 비터치 화면의 임무 가독성과 알림 간격.
- `scripts/check-input-lifecycle.mjs`, `scripts/check-mission-expansion.mjs`, `scripts/check-expert-usability.mjs`: 중단·시간·설정·실제 번개·지원 지형 이탈의 회귀 검사.
- `scripts/check-qa.mjs`, `scripts/check-hong-kong-resilience.mjs`: 이전 설정을 가정하던 검사 수정. 실제 입력 경로와 지형 준비 조건은 계속 검사한다.

## 검증과 재현

`npm run test:expert-usability`는 실제 구현을 호출해 화면 효과 감소, 키 재배정, 입력 수명주기와 개인 플레이를 검사한다. `node scripts/check-mission-expansion.mjs`는 착지 중 진행률·지지 이탈·배송 순서·저장 실패·로딩 복구를 검사한다.

`QUALITY_URL=http://127.0.0.1:5194 npm run qa:expert-usability`는 개발 서버에서 Chrome으로 실행한다. 튜토리얼 토글 설명, 실제 W 이동, 메뉴에서 임무 시작, 390px 안내 폭과 알림 비겹침, 세 목적지의 지형 지지와 대기 조건에 의한 완료, 실제 W 이동과 좌클릭 타격, 터치 에뮬레이션을 확인한다. 별도로 실제 프로덕션 빌드의 시작과 개발 검사 API 부재도 확인했다(`production.json`). 목적지 도착은 재현을 위한 위치 배치이며 직접 이동한 전체 임무 플레이로 주장하지 않는다. 결과는 `browser.json`, 화면은 `desktop.png`, `narrow.png`, `touch.png`에 저장한다.

별도로 세션 전환·전체 게임 교차 기능·시민·차량·지형 복구·네트워크 장애 검사와 프로덕션 빌드를 실행했다. 첫 검사 결과는 `regressions/suite.json`, 이어서 수행한 결과는 `regressions/final-suite.json`, 모션 수정 과정의 중간 재검사는 `regressions/postfix-suite.json`에 기록한다. 최종 수정 이후 결과는 `regressions/final-suite.json`을 따른다. 최초 실행과 수정 전 실패 요약(`regressions/before-final-rechecks.json`)을 최종 검증 기록과 함께 보존한다.

## 후속 제작 순서

1. 실제 사용자가 첫 안내를 마치고 첫 임무를 완료할 수 있는지 관찰하고 이탈 구간을 측정한다. 기존 `PlayStudy` 자료를 사용하며 임의의 완료율을 만들지 않는다.
2. 구역별 랜드마크와 반복 이동 경로의 시각적 식별성을 설계한다. 충돌 지형과 스윙 부착점을 유지한 작은 구역부터 제작한다.
3. 이동·전투·차량을 연결하는 상황형 임무를 제작한다. 먼저 한 개를 끝까지 완성하고 실패·재도전·저장·중단 복귀까지 검증한 후 확대한다.
4. 실제 휴대기기와 운영 온라인 세션에서 장시간 프레임·발열·연결 복귀를 검사한다. 에뮬레이션과 단위 검사를 실기기 인증으로 표시하지 않는다.

새 경제·해금·전투 밸런스·대규모 지형 변경은 이번 검토의 근거만으로 임의 도입하지 않았다. 현재 확인된 사용성·안정성 문제는 위 파일에 적용했고, 콘텐츠 제작과 운영 환경 검증은 남은 작업으로 구분한다.

### 검사 기준을 수정한 이유

- 전투 자세는 현재 모드 전환만으로 활성화되지 않는다. 자세를 비교하는 실입력 검사에 실제 자세 유지 입력을 넣었다. 회피 무적 검사는 시작 즉시가 아니라 구현된 활성 구간을 사용한다.
- 크로스와 오른손 훅은 현재 사용 중인 `Mixamo Cross Punch.fbx`, `Mixamo Rear Hook.fbx`를 검사한다. 이전 절차 생성 훅의 고정 팔꿈치·반대 손 좌표 대신 원본 출처, 타격 구간, 유한한 관절 위치와 손 경로 연속성을 확인한다. 이동 타격은 잽·크로스·오른손 훅을 각각 고정해 24·60·144FPS와 걷기/질주 조합을 검사한다. 렌더 관절 범위와 이동 타격의 기존 손 속도 기준은 유지했다.
- 발목·발가락 뼈의 피벗은 부츠 외곽보다 아래에 놓일 수 있다. 관통 검사는 모든 프레임의 실제 스키닝된 밑창을 사용하도록 바꾸고 기존 1cm 관통 한도를 유지했다. 지지 중 피부 간격 5mm/35mm와 발 회전 속도 제한도 유지한다.
- 나머지 도시 레이어 수·품질 거리·강공격 키의 기대값은 현재 구현과 맞췄다. 테스트를 통과시키기 위해 게임의 안전 지형 조건이나 타격 판정 시간을 완화하지 않았다.

### 모션 복귀 수정의 검증

크로스 타격 강도가 낮아질 때 가슴 방향 보정을 한 프레임에 제거하던 경계를 연속적인 해제로 바꿨다. 타격 유효 시간과 공격력은 유지했다. 수정한 크로스는 양쪽 외형·24/30/60/144FPS의 별도 관절 검사 16개, 8,454프레임을 통과했다(`cross-joints/results.json`). 전체 모션 검사 중 실시한 304개/40,284프레임 검사와 구분한다.

## 최종 결과

- 전체 검사 스크립트 90/90 통과. 최초 실행의 실패와 수정 전 요약은 별도 보존하고 재검사 결과를 `regressions/final-suite.json`에 반영했다.
- 잽·크로스·오른손 훅을 각각 고정한 이동 타격 검사를 포함해 접지·자세·조합 검사를 통과했다. 마지막 키 배정 기대값 수정 이후 자세 검사 23개도 통과했다.
- Chrome 브라우저 시나리오 7/7 통과, 처리되지 않은 오류 0개. 데스크톱·390px 비터치 창·터치 에뮬레이션을 확인했다.
- `npm run build`와 실제 프로덕션 빌드 시작 검사 통과. 개발용 품질 API는 프로덕션에서 노출되지 않았다.
- 실제 휴대기기의 장시간 발열·배터리·프레임 유지와 운영 서버의 실사용자 대전은 이번 로컬 검증에 포함하지 않았다.

종합 기록: `validation.json`. 이어서 재현하려면 `npm run test:release-quality` 또는 전체 `npm test`를 사용한다.
