# 스파이더맨 전체 모션 적용 범위 검토

검토일: 2026-10-11. 이번 검토에서는 플레이 로직과 원본 모델을 변경하지 않았다.
진단 스크립트와 결과만 추가했다.

## 결론

프로젝트의 FBX 18개를 실제 spiderman.glb에 리타게팅하여 60Hz 기준 총 3,010개의
자세를 수치 검사했다. 전부 65개 뼈 매칭과 유한한 트랙 값을 통과했다.
이것은 **뼈대 적용 가능** 판정이다. 모든 동작의 시각적 자연스러움, 지면 접촉,
모든 전환 및 모든 게임 분야가 완성됐다는 판정은 아니다.

현재 12개 파일을 로드하지만 실제 Character.update에서 선택하는 동작은 9개다.
3개는 검증 화면에서만 선택할 수 있으며, 나머지 6개는 플레이 로더에 연결되지 않았다.
기존 npm test는 다시 통과했다. 미연결 6개의 전체 시각 검사는 이번 수치 검사에 포함되지 않는다.

Downloads의 Walking (1).fbx는 프로젝트 Walking.fbx와 SHA-256이 같고,
Falling (1).fbx는 Falling Idle.fbx와 SHA-256이 같다. 둘 다 별도의 새 동작은 아니다.
Falling/Falling (2)/Falling Idle의 파일 자체가 모두 동일하다는 뜻은 아니다.

## 코드에서 확인한 자연스러움 공백

1. **제자리 회전 미연결**: Character.js의 update는 pendingTurn을 비우고
   walk/run만 선택한다. 좌우 회전 파일이 로드됐다는 이유로 실제 회전 모션이
   게임에 적용됐다고 판단할 수 없다.
2. **일반 달리기 속도 구간 없음**: 현재 걷기와 Fast Run만 사용한다.
   Jogging/Running을 추가하려면 속도 구간, 보폭 및 위상 전환이 필요하다.
3. **웹 집은 점프 자세 재사용**: SwingPhysics.performAirJump는 웹 집 속도를
   주지만 state를 JUMPING으로 지정한다. 전용 웹 집 자세나 발사/회수 클립은 없다.
4. **벽 달리기는 지상 run 회전 재사용**: 벽 방향으로 모델을 회전시키지만,
   벽 전용 발/손 접촉 또는 벽 기어가기 동작은 없다.
5. **구르기 이동은 원본과 분리**: 리타게팅은 골반의 수평 root 이동을 제거한다.
   현재 컨트롤러는 roll의 원본 이동 거리를 받아 실제 위치를 옮기지 않는다.
   따라서 원본의 구르기 거리와 물리 이동이 일치한다고 보장할 수 없다.
6. **일반 착지 전용 반응 없음**: 강한 충격에서는 roll이 있지만, 가벼운 착지는
   대기/걷기로 블렌딩된다. 착지 무릎 굽힘·균형 회복을 충분히 표현하지 못할 수 있다.
7. **공중 묘기는 모델 전체 회전**: 전용 몸 말기·팔/다리 자세를 가진 공중 묘기
   클립이 아니라 모델 회전으로 표현한다.
8. **발 고정 IK 없음**: 수치상 뼈 매칭이나 프레임 검사를 통과해도 발 미끄러짐,
   높이 차, 지형/소품 접촉의 자연스러움은 별도 해결 대상이다.

## 전체 게임 분야별 필요한 모션

아래는 현재 파일명으로 외부 서비스에 실제 존재한다고 주장하는 목록이 아니라,
게임 동작을 구성하기 위한 필요한 기능별 클립/상태 목록이다.

| 분야 | 현재 커버 | 추가 검토/제작이 필요한 동작 |
|---|---|---|
| 기본 이동 | 대기·걷기·빠른 달리기·정지 | 조깅/일반 달리기 연결, 가속, 후진, 옆걸음, 이동 중 급회전, 제자리 회전 연결 |
| 점프·착지 | 상승 점프 구간·자유 낙하·강한 착지 구르기 | 준비 자세, 달리며 점프, 짧은 단차, 가벼운/중간 착지, 히어로 착지, 낙하 높이별 연결 |
| 거미줄 이동 | 스윙 루프·손 방향 IK | 좌/우 거미줄 발사, 스윙 진입, 몸 펌핑, 줄 바꾸기, 손 놓기, 웹 집 시작/비행/종료, 슬링샷 준비/발사 |
| 벽·천장 | 지상 run을 벽 방향으로 회전 | 벽 부착, 벽 대기, 위/아래/좌/우 기어가기, 벽 전용 달리기, 벽 점프, 모서리 넘기, 천장 이동 |
| 옥상·파쿠르 | 기본 점프만 | 난간 잡기, 매달리기, 옥상 올라서기, 장애물 넘기, 슬라이딩, 낮은 장애물 통과 |
| 공중 묘기 | 모델 회전으로 뒤집기 | 몸 말기, 앞/뒤 공중제비, 비틀기, 묘기 시작과 정상 자세 복귀 |
| 전투·방어 | 관련 시스템/파일 확인되지 않음 | 전투 대기, 펀치·킥·공중 공격, 거미줄 공격, 회피, 피격, 넉백, 넘어짐, 기상 |
| 부상·회복 | Injured Idle 파일만 보유 | 부상 이동, 착지 충격 반응, 균형 상실, 회복, 쓰러짐, 사망/리스폰 전환 |
| 상호작용·연출 | 해당 전용 파일 없음 | 앉기/웅크리기, 대상 바라보기, 물건 잡기, 상황별 등장·종료 동작 |

현재 웹 스윙 게임을 자연스럽게 만드는 우선순위는 기존 이동/제자리 회전 연결,
착지·구르기의 물리 동기화, 웹 집/스윙 진입·이탈, 벽 접촉이다.
전투 등 아직 구현되지 않은 분야는 모션만 붙여도 기능이 생기는 것이 아니므로
해당 게임 시스템과 함께 별도로 구현해야 한다.

## 재현

- 전체 보유 파일 수치 검사: `node scripts/audit-all-motions.mjs`
- 현재 준비된 플레이 클립/컨트롤러 회귀 검사: `npm test`
- 원시 결과: `all-motion-audit-2026-10-11.json`
- 현재 검증 화면은 로드된 12개만 제공: http://localhost:5173/?motionReview

임의의 새 FBX가 동일하게 적용된다는 보장은 없다. 새 파일마다 뼈 이름,
축/기준 자세, 크기, 유효 take, root 이동, 접촉 및 전환을 다시 검사해야 한다.
