# 실제 화면 기반 모션 재검토

## 판정

FBX 18개/파생 포함 20개 액션의 대표 자세를 브라우저에서 직접 확인했다.
전체 이동·정지·점프, 좌우 회전, 중간 낙하, 높은 낙하, 웹 집, 스윙 해제,
벽 달리기→옥상 진입을 검증 화면에서 실행하고 주요 전환을 정지해 검사했다.
실제 도시 게임에서도 마우스 잠금 없는 모드로 시작, 걷기 입력, 입력 해제,
지상 점프와 카메라 추적을 확인했고 마지막 브라우저 오류 로그는 비어 있었다.

이 판정은 모든 모션의 매 프레임과 모든 입력 조합, 지형·충돌·리타게팅을
시각적으로 완전 검증했다는 뜻이 아니다. 아래 남은 한계를 포함한다.

## 이번에 확인하고 수정한 문제

| 문제 | 수정 및 확인 |
|---|---|
| 지면 충돌 후 즉시 반환하여 벽 충돌 누락 | 물리 처리의 조기 반환 제거, City의 벽 검사 우선. 실제 City 기반 걷기/구르기 벽 통과 회귀 검사 |
| 착지 직후 낙하 자세가 남아 몸이 뜸 | 예상 접촉 0.3초 전에 공중 준비 자세 선택, 착지/구르기 블렌딩 0.06초. 동일 고층 낙하 전환 재촬영 |
| 벽 달리기에서 몸 전체가 옆으로 누움 | 캐릭터 척추 축을 세계 수직으로 유지하고 벽을 바라보게 변경. 수정 전/후 직접 비교 |
| 벽 이동이 보폭보다 지나치게 빠름 | 수직 22→6.5m/s, 수평 16→4.5m/s. 재생 속도와 기존 질주 기준에 맞춤 |
| 대기 중 발의 작은 이동 / 충돌 여유가 렌더 높이에 반영 | 대기 발 위치를 양다리 IK로 고정, 지상 10cm 충돌 패딩을 렌더에서 상쇄. 접촉 높이·발 위치 고정 수치 검사 |
| 카메라 기울기가 프레임 속도에 의존 | 시간 기반 감쇠, 30/60/144Hz 회귀 검사 |
| 흔들림이 실제 추적 위치에 누적 | 렌더 오프셋으로 분리, 충돌 대상이 있는 도시에서는 흔들림 억제 |
| 마우스 잠금 실패/변화로 시작 화면 복귀 | 잠금을 실제 얻었다가 잃었을 때만 정지. 잠금 없는 휠 버튼 드래그 시작 옵션 추가, 도시 게임에서 시작·키보드 이동 확인 |
| 시점 드래그와 웹 발사가 같은 입력 | 잠금 없는 시점 드래그를 휠 버튼으로 분리하여 좌클릭 발사와 충돌하지 않게 변경 |
| 벽 점프 직후 재부착 가능 | 이탈 방향 속도와 0.3초 재부착 쿨다운 검사. 실제 City 기반 벽 점프 회귀 검사 |

검증 화면에는 모션 선택 이력과 전환 순간 자동 정지를 추가했다.
`inspect-rig.mjs`의 Idle 원본 대비 좌우 허벅지/종아리 방향 오차는 0.00도였다.
화면상 발이 높아 보인다는 이유만으로 축 오류라고 단정하지 않고, 발 조인트와
실제로 스키닝된 신발 정점의 높이도 별도로 확인했다.

## 남은 한계와 우선순위

1. 벽 달리기는 지상 질주를 보정한 파생 표현이다. 전용 벽 보폭·발 접촉 IK가
   없고 양손 보정만으로 모든 순간의 손 접촉/관통을 보장하지 않는다.
2. 웹 집과 스윙 진입·해제에는 전용 원본 클립이 없다. 원본 점프/스윙과 IK 기반
   표현이며 팔·다리의 스파이더맨 특유 동작은 전용 제작/다운로드가 필요하다.
3. 발 위치 고정은 일반 대기에 한정된다. 이동 중 발 고정, 경사면·소품 대응,
   급격한 180도 입력 전환과 체중 이동은 추가 작업 대상이다.
4. 옥상 진입은 위치 전환이다. 난간을 손으로 잡고 올라가는 전용 모션은 없다.
5. 공중 묘기는 여전히 모델 전체 회전 방식이다. 몸 말기/비틀기 클립이 아니다.
6. 도시의 모든 장식 소품을 충돌/IK 대상으로 검증하지 않았다. 전투·천장 이동·
   부상/체력·사망 같은 미구현 분야도 이번 검증에 포함하지 않았다.
7. 마우스 잠금 모드는 이 브라우저에서 안정적으로 완료하지 못했다. 잠금 없는
   시작과 키보드 이동은 확인했지만 휠 버튼 드래그의 실제 회전은 코드 검사 범위다.
