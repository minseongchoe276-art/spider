# Spider-Man Hong Kong Web Runner — 전체 자가진단

기준일: 2026-10-11  
범위: 현재 기본 홍콩 3D Tiles 플레이 경로, 게임 로직, 캐릭터/애니메이션, 입력/UI, 사운드/VFX, 성능, 접근성, 배포/의존성, 자동 검증.  
이번 작업은 진단만 수행했으며 게임 소스는 수정하지 않았다.

## 요약 판정

현재 상태는 **플레이 가능한 프로토타입/기술 데모**다. 홍콩 도시 스트리밍, 캐릭터, 이동·점프·스윙·벽 달리기, HUD가 연결되어 있고 빌드와 자동 테스트는 통과했다. 하지만 장애 대응, 실제 홍콩 전역 탐험, 게임 모드 완성도, 성능 검증, 접근성/기기 지원 및 배포 준비는 완제품 기준에 미달한다. “모든 분야에서 완벽히 검증됨”으로 볼 수 없다.

## 우선순위 높은 결함·위험

### P1 — 모델 파일 로드 실패 시 시작 불가

`src/Character.js`의 `loadCharacter()`는 GLB 로드 예외 때 프록시 캐릭터를 남기고 `onLoaded()`를 부르지만 `isLoaded`를 true로 만들지 않는다. 반면 시작 버튼 처리(`src/main.js`)는 `character.isLoaded`가 false면 조용히 반환한다. 따라서 모델 파일이 없거나 GLB가 깨지면 로딩 화면에서 빠져나와도 게임 시작 버튼이 작동하지 않을 수 있다. 오류 메시지와 프록시 플레이 가능성을 포함한 복구 경로가 필요하다.

### P1 — 홍콩 데이터 장애 때 무한 로딩 가능

타일 로드 오류는 콘솔 경고 및 선택적 `?debugCity` 화면에만 기록된다(`src/UrbanGroundCity.js`). 유효한 충돌면을 찾지 못하면 `isReady`가 계속 false이며 대체 맵, 재시도, 제한 시간, 사용자용 오류/재시도 안내가 없다. 네트워크, CORS 프록시, upstream 데이터 장애 시 이용자는 멈춘 로딩 화면만 보게 된다. 캐릭터의 각 FBX 애니메이션은 순차 로드되고 개별 실패는 경고만 남기므로, 긴 로딩과 부분 애니메이션 상태도 구분해 안내하지 않는다.

### P1 — 홍콩 맵에서 플레이 가능한 범위가 코드로 제한됨

`src/SwingPhysics.js`는 좌표의 `|x|` 또는 `|z|`가 2,400m를 넘으면 안전 위치로 리셋한다. 이는 자유 탐험 도시 맵의 경계를 명시적으로 제한하며, 의도된 게임 월드 경계인지 데이터/충돌 한계인지 UI에 표시하지 않는다. 사용자가 그 너머의 홍콩 지역을 탐험할 수 있는지와 충돌 타일 유지 상태는 확인되지 않았다.

### P2 — 타임트라이얼은 구현 파일만 있고 플레이 루프에 연결되지 않음

`src/main.js`에서 `TimeTrialSystem`을 생성하지만 실행 중 `toggle/start/update`를 호출하거나 완료 UI를 연결하지 않는다. 따라서 보이는 게임에는 코스 링이 활성화되지 않고, 모드 진입/완료/결과 기록도 없다. 현 상태는 사용 불가한 고아 기능이다.

### P2 — 큰 홍콩 씬에서 프레임 저하 위험

- 매 프레임 `findBestAnchor()`가 타일 렌더 메시 전체를 상대로 중심 광선과 보조 광선을 쏜다(`src/SwingPhysics.js`). 메시 수가 많은 구역에서 비용이 커질 수 있다.
- 카메라는 한 번 갱신할 때 중심/주변 5개 광선을 목표 위치, 보간 위치, 흔들림 위치에 반복 적용한다. 도시의 Rapier 월드와 시각 메시 양쪽 질의가 수행될 수 있다(`src/Camera.js`). 실제 기기에서 FPS/프레임타임 프로파일은 없다.
- 충돌 생성은 프레임마다 한 메시만 처리하지만, 그 한 메시의 모든 삼각형을 메인 스레드에서 순회하고 월드 좌표로 바꾸는 비용은 제한하지 않는다(`src/StreamedCollision.js`). 매우 큰 타일 하나가 순간 프레임 정지를 만들 가능성이 있다.
- 350개 초과 시 900m 바깥 collider만 제거한다. 가까운 collider가 계속 350개를 넘으면 상한을 강제하지 못한다. `meshes` 맵은 아직 처리 전인 null 항목도 포함한다.
- 3D 타일 캐시 예산은 약 512MiB 설정이며 충돌 지오메트리, GPU 텍스처, 브라우저/탭의 나머지 메모리는 별도다. 총 메모리 사용량과 저사양 Mac에서의 안정성은 측정하지 않았다.

### P2 — 충돌·맵 스트리밍 장거리 동기화는 미검증

충돌 생성 때 한 메시에서 플레이어 주변 ±650m X/Z 삼각형만 저장하고 해당 메시 UUID를 처리 완료로 기록한다(`src/StreamedCollision.js`). 동일 메시가 계속 활성인 채 플레이어가 그 잘린 범위를 벗어나면 나머지 삼각형을 다시 만들지 않을 가능성이 있다. 현재 타일의 공간 분할이 이를 항상 막아주는지 실데이터 장거리 이동 검증이 필요하다. 또한 오래된 LOD collider를 2초간 보존하는 정책은 순간적인 이중 표면/높이 차 또는 지지면 잔존을 만들 수 있다.

### P2 — 시작 위치 주변 화면이 깔끔하지 않음

실제 프로덕션 미리보기의 스모크 화면에서 홍콩 도시와 캐릭터가 로딩되는 것은 확인했으나, 캐릭터가 큰 평면형 건물 면/경계에 매우 가까이 보여 첫 장면이 답답하고 타일의 시각적 불연속도 드러났다. 이는 스폰 검증의 여지와 원본 3D 데이터의 품질 문제를 함께 시사한다. 시작 지점에서 여러 방향의 여유 공간, 지붕 가장자리 거리, 카메라 시야를 수동/자동 검증하지 않았다.

## 나머지 분야 평가

### 이동·물리·조작

120Hz 고정 스텝, 프레임률 비교(30/60/120/144), 점프 버퍼/코요테 타임, 캡슐 충돌, 벽/천장/경사/계단, 스윙 속도 상한, 벽 달리기 파사드 및 지붕 감지에 대한 단위 테스트가 있다. 이는 유의미한 기반이다. 다만 테스트는 작은 합성 지오메트리 중심이며 도시의 랜덤 지형/타일 LOD 경계/긴급 충돌, 멀티 입력 조합, 실기기 체감은 보장하지 않는다. 중력 28m/s², 질주 6.5m/s, 최대 속도 48m/s 등은 현실 물리라기보다 의도적인 아케이드 수치로, ‘현실적인 물리 법칙’ 완성으로 간주할 수 없다.

### 캐릭터·애니메이션

모션 검사와 리타게팅 검증은 존재하고 테스트는 통과했다. 다만 시작에 여러 FBX를 순차로 모두 받으며 사용자에게 개별 진행/필수 모션 오류 복구를 제공하지 않는다. 특정 상태 클립이 빠져도 게임 진입을 허용하고 `fadeToAction()`은 해당 액션이 없으면 이전 동작을 유지한다. TGA 텍스처 누락/대체 및 FBX 초과 스킨 웨이트 경고가 검사 실행에 반복된다(게임 내에서 사용하는 애니메이션에 어떤 시각적 영향을 주는지는 별도 확인 필요). 전용 벽 달리기/웹 집 모션이 아닌 기존 클립과 절차 보정에 의존한다.

### 카메라·UI·접근성·플랫폼

기본 키보드/마우스, 포인터락 실패 시 드래그 경로, 도움말/HUD, 브라우저 포커스 상실 시 입력 해제는 구현되어 있다. 반면 터치 조작/게임패드, 키 재설정, 자막/시각적 사운드 신호, 텍스트 대비·화면낭독기 전체 지원, 감소된 모션 설정, 작은 화면 레이아웃은 검증되지 않았다. WebGL 생성 실패/컨텍스트 손실 사용자 안내도 없다. 실 브라우저 호환성 행렬(특히 Safari/macOS)은 확인하지 않았다.

### 게임 루프·콘텐츠

현재 확인되는 중심 루프는 자유 이동/스윙 샌드박스다. 타임트라이얼은 연결되지 않았고, 목표·진행 저장·최고 기록·체크포인트 재시작·설정 화면·온보딩/튜토리얼 등 완결된 반복 플레이 루프는 확인되지 않았다. `stuntScore`도 점수 UI/저장과 연결되지 않은 상태로 보인다. 사용자가 기대하는 “완성 게임”과 “웹 스윙 기술 데모”의 범위를 먼저 확정해야 한다.

### 오디오·시각효과

Web Audio 기반 효과음/바람, 속도선, 착지/웹 파티클이 있지만 음악, 공간 음향, 거리/상태별 음향 믹스, 오디오 접근성은 없다. 느린 조준은 물리 시간만 스케일하며 `slowMoFilter`는 선언만 되어 있어 실제 오디오 피치/시간이 게임과 함께 느려지지 않는다. WebGL 성능과 파티클 가독성은 장치별 확인이 필요하다.

### 보안·라이선스·배포

`npm audit --omit=dev`: 취약점 0건(현재 lockfile/registry 결과). 프로덕션 빌드는 성공했지만 단일 JS 번들이 minify 후 약 5.22MB(압축 약 1.89MB)로 Vite 500kB 경고가 발생한다. 개발/미리보기는 Vite 프록시를 사용하지만 정적 호스팅 자체에는 홍콩 타일 프록시가 포함되지 않으므로 배포에는 별도의 서버 프록시/CORS 설계가 필요하다. 프로젝트/모델/애니메이션/원본 도시 데이터의 재배포 권리, 출처 표기, 제3자 글꼴 조건은 배포 전 확인해야 한다. 현재 디렉터리에서 Git 작업 트리 여부는 확인되지 않았으므로 변경 추적/회귀 비교도 보장할 수 없다.

## 검증된 것과 검증하지 않은 것

실행한 검사:

- `npm test` 통과: 모션 검사, 컨트롤러 회귀, 합성 메시 기반 gameplay/물리 검사.
- `npm run build` 통과: Vite 프로덕션 빌드. 단, 5.22MB 단일 번들 경고 있음.
- `npm ls --depth=0` 정상.
- `npm audit --omit=dev`: 취약점 0건.
- 프로덕션 미리보기에서 홍콩 3D 타일 로딩 완료와 시작 후 플레이 장면 확인.

미검증: 수십 분 장시간 플레이, 홍콩 전역 실제 주행, LOD 전환/다중 타일 충돌 완전성, 네트워크 끊김/재시도, 저사양 Mac GPU·메모리, Safari/iPhone/iPad, 키보드 전용 접근성, 사용자 데이터/저장, 정적 호스팅 배포, 법률/라이선스 확인, 실 FPS·프레임타임 측정.

## 권장 작업 순서

1. 실패 복구: 캐릭터 모델 실패 시 프록시로 플레이 가능하게 하고, 타일 실패 시 오류 상태/재시도/절차 도시 대체 경로를 제공.
2. 월드 범위/스폰 기준 확정: 2.4km 강제 리셋을 의도된 경계로 표시하거나 탐험 범위를 데이터 스트리밍과 맞추고, 스폰 공간·카메라를 실제 지형에서 검증.
3. 게임 모드 완성: 타임트라이얼, 점수, 시작/일시정지/완료/재시작 UX를 연결하거나 죽은 모듈을 제품 범위에서 제외.
4. 성능 측정 후 최적화: Mac Safari/Chrome에서 GPU 프레임타임, CPU 긴 프레임, JS/WASM/GPU 메모리, 타일/충돌 대기열을 기록하고 조준 레이/충돌 생성 예산화.
5. 배포 품질: 번들 분할/로딩, 서버 프록시, 라이선스/출처, 장애 로깅, 브라우저 호환성·접근성 검증.
